# Basketball Autochess — 數值模型與 OVR 計算器

籃球自走棋的 possession 機率模型。這個 repo **只做數值層**：十四屬性 → 事件機率 → Monte Carlo。
沒有商店、卡牌、連鎖、裝備——那些等數值地基固定之後再疊。

設計文件在 [`docs/`](docs/)：[數值模型](docs/數值模型.md)、[隊伍卡表](docs/隊伍卡表.md)、[卡牌設計](docs/卡牌設計.md)。
上游 GDD v0.1（子捷／Eve）不在 repo 裡。

## 跑起來

```bash
node test/run_tests.js      # 驗證清單（51 項）
node test/marginal.js       # 每個屬性值多少分（判斷屬性該不該存在）
node test/ovr.js            # 由模擬逆推 OVR 與費用分級
node test/calibrate.js      # PR50 對 PR50 是否收斂到聯盟平均
node test/variance.js       # 賽制對「實力→勝率」的影響
node test/round_robin.js    # 五隊循環賽
node test/diagnose.js       # 球權分布、出手區域、防守否決
node gen_note.mjs           # 重新產生 docs/隊伍卡表.md 的數據區段

python -m http.server 8770  # 然後開 http://127.0.0.1:8770 用計算器 UI
```

`src/teams.js` 跟 `docs/隊伍卡表.md` 的 GENERATED 區段都是自動產生的，要改卡表請改 `gen_teams.mjs` 再重跑 `node gen_teams.mjs`。

## 架構

```
src/constants.js          錨點表、夾值、校準目標
src/probability_model.js  屬性 -> possession 事件機率（四層分解）
src/simulation_engine.js  possession loop + Monte Carlo
src/teams.js              五支真實隊 + PR50 基準隊 + 五小/雙塔測試隊（自動產生）
src/rng.js                種子亂數（可重現）
gen_teams.mjs             百分位 -> 屬性，產生 teams.js
gen_note.mjs              跑模擬，寫回 docs/隊伍卡表.md 的 GENERATED 區段
index.html                計算器 UI
```

參考 [Lanternko/Nine_innings](https://github.com/Lanternko/Nine_innings) 的四個部件：
錨點表逆推、分段線性插值當 S-curve、tanh 只用在修正因子、階層式機率分解最後 normalize。

「基礎屬性 → composite」的分層抄自 [zengm](https://github.com/zengm-games/zengm)（Basketball GM）。
**只抄結構，不抄常數**——zengm 的球員是自己隨機生成的，它的權重是為那個尺度校準的，
搬到「真實賽季百分位」尺度上會全錯而且不會報錯。

## 十四屬性

| 屬性 | 逆推來源 |
|---|---|
| 三分 | `leaguedashplayershotlocations` Corner 3 + Above the Break 3 |
| 中投 | 同上，Mid-Range |
| 近射 | 同上，Restricted Area + In The Paint (Non-RA) |
| 罰球 | `FT_PCT`（低量用 log(FTA) 迴歸當先驗） |
| 切入 | `FTA/FGA` 與禁區出手佔比的合成百分位（**創造出手，不是終結**） |
| 傳球 | `AST_PCT` |
| 籃板 | `REB_PCT` |
| 盯防 | `leaguedashptdefend` DefenseCategory=**3 Pointers** 的 `PLUSMINUS` |
| 協防 | 同上，DefenseCategory=**Less Than 6Ft** |
| 體力 | MPG |
| 肉體 | 身高 + 體重（0.45/0.55 標準化加權）。**臂展無公開資料** |
| 無球 | `CATCH_SHOOT_FG3A`（接球投三分的量） |
| 擋拆 | `SCREEN_ASSISTS` |
| 失誤 | `TOV/(FGA+0.44*FTA+**AST**+TOV)` 的反向百分位 |

**十四項裡有十項只需要 box score 或 shot locations，1996-97 起零斷層**，
所以三個時代都能定錨。只有無球、擋拆、盯防、協防四項依賴 tracking（2013-14 起）
或 hustle（2016-17 起）。

## 模型

錨點全部來自 NBA 真實分布（rotation player: G≥30, MPG≥20），`pr1→40 / pr50→70 / pr99→99`，
且**每名球員在自己那個賽季的母體內定錨**——2016 年的球員不會被現代三分潮稀釋。

```
L1  possession 大類    TOV / FOUL / SHOT
L3  命中（先算，因為出手選擇要看期望值）
      P(三分) = curve_3pt(三分) × (1+tanh(隊友無球)) × (1+tanh(隊友傳球)) + pm(盯防)
      P(中投) = curve_mid(中投)                                        + pm(盯防/協防各半 × 0.6)
      P(近射) = curve_short(近射) × (1+tanh(隊友擋拆)) × (1+tanh(肉體差))
                                 × (1+tanh(隊友傳球))                  + pm(協防)
      P(罰球) = curve_ft(罰球)   ← 不受任何防守影響
L2  出手區域           p(zone) ∝ 聯盟佔比 × exp(ΔEV / EV_TEMP + 可及性 / ZONE_TEMP)
L4  未命中 -> 進攻籃板（延續同一 possession）
```

`pm()` 是防守者的 `PLUSMINUS`（被他防守時對手命中率的絕對增減量），**直接相加**，
不轉成 tanh 乘數——因為它的原始語意就是命中率的增減量。進攻側的無球／擋拆／肉體
沒有現成量表，才走 tanh 乘數。兩側形式不對稱是刻意的。

**肉體差 = 持球者肉體 − 對方全隊平均肉體。** 五小陣容因此被大個子克制。
肉體另有兩個次要作用：隊伍籃板權重佔 30%、協防 +0.25×(肉體−70)。

體力照 Nine_innings 的 `pitcherEffectiveness`：**削弱屬性，不加減機率**。

### 中距離為什麼存在

純看期望值，中投（2 × .42 ≈ .84）永遠輸給禁區（2 × .58 ≈ 1.16）與三分（3 × .36 ≈ 1.09）。
NBA 就是這樣把中距離殺掉的。所以模型裡中投不是「另一種選擇」，而是**兩條路都被斷之後剩下的那條**：

```
可及性(三分) -= (盯防 − 70) × 0.45
可及性(近射) -= (協防 − 70) × 0.55
可及性(中投)  沒有人守
```

實測（同一支 PR50 進攻，只改對手防守）：

| 對手盯防/協防 | 近射 | 中投 | 三分 | 每回合得分 |
|---|---|---|---|---|
| 40 / 40 | .501 | .052 | .447 | 1.370 |
| 70 / 70 | .475 | .110 | .415 | 1.161 |
| 99 / 99 | .421 | .215 | .364 | 0.945 |

中投佔比 4 倍成長，而且中投屬性的邊際價值也跟著跑出來：
45→95 對弱防守只值 +0.004 分/回合，對強防守值 **+0.031**。

### 傳球必須影響得分，不能只重分配球權

第一版的傳球只影響誰出手——邊際價值量出來是 **+0.000**。
只重新分配球權的屬性等於不存在。

補上的機制：**隊友傳球提升出手品質**（接球投就是比自己運球拔起來準），
以及提升禁區可及性。這跟無球是兩件事——無球是「我跑出空檔」，
傳球是「有人把球準時送到」。補完後 **+0.076**。

### 誰出手

不是靜態 usage 權重。每次進攻機會都算五個人各自持球的期望得分，softmax 抽：

```
usage_i ∝ exp( (期望得分_i + 1.10 × 創造力_i / 100) / 0.22 )
創造力 = 0.30×三分 + 0.20×中投 + 0.05×近射 + 0.15×切入 + 0.50×傳球 − 0.15×(無球−70)
```

傳球（`AST%`）是分開持球創造者與定點射手的主力訊號。加進去之後對真實 USG%
的相關係數從 **0.528 → 0.729**、平均絕對誤差 **6.05 → 4.54pp**。

值得記一筆：`AST%` 單獨一個欄位就有 r = 0.506，而手調三個版本的創造力公式只有 0.458。
最後夾在 8.5%–34.5%（NBA 真實範圍）再正規化。

## 踩過的坑

**1. 兩分不能當成一個區。**
舊版只有 3PT / RIM 兩型態，中距離被砍掉，理由是中距離樣本兩端是假極值。
後果是系統性低估中距離時代——Kobe 2001-02 的投射被算成 41。
真正的解法不是砍，是**用出手數當先驗**（下一條）。

**2. 「沒出手」不等於「聯盟平均」。**
用經驗貝氏把命中率往聯盟均值收縮，會讓整季 1 次三分出手的 Shaq 拿到 pr 50。
統計上對，遊戲上錯——不投的人本來就比較差。改成先用 `log(出手數)` 迴歸命中率，
把迴歸線當先驗：Shaq 三分變 pr 8.1、Tristan Thompson（0 次出手）pr 0。

**3. Monte Carlo 要先累加次數再算比率。**
中投一場只有約 3 次出手，把每場的比率平均會讓投 0 次的場次貢獻 0，
中投命中率被壓低 4 個百分點。

**4. possession 的定義要對。**
進攻籃板**延續同一個 possession**，不是新的一次。一開始寫成每次出手都算一個回合，
結果先攻方因為多搶進攻籃板而多打，同隊對打產生 3.6% 的假優勢。

**5. TOV 曲線是「每次進攻機會」不是「每 possession」。**
一個 possession 平均有 ~1.18 次機會，複合後才是實際失誤率。

**6. 分類別的防守 PLUSMINUS 要收縮。**
`3 Pointers` 與 `Less Than 6Ft` 兩類的原始 pr1/pr99 到了 ±.19 與 ±.21，
但那是樣本雜訊灌水的——每人每場只守約 4 次三分出手。直接用會讓 pr99 防守者
把對手三分從 .364 砍到 .184。以 `Overall` 類別（樣本大得多，±.08）反推收縮係數。

**7. EV_TEMP 太小會讓屬性升高反而變弱。**
混合期望值對某區 EV 的偏導是 `w_z × (1 + (ev_z − 混合均值)/T)`，
當 `T` 小於「最差區與均值的差距」時是負的——中投練高只是讓你多投爛球。
實測 0.55 是臨界值，取 0.60。單調性測試會抓到這個。

**8. 出手區域佔比要夾在球隊真實範圍。**
雷霆（Chet 近射 96、Hartenstein 91、SGA 89）不夾的話會把 72% 的出手塞進禁區。
真實球隊上限約 .62——因為防守會塌陷，而 PR50 防守在模型裡不會自動塌陷。

## 已知限制

- **臂展沒有公開資料。** 肉體只用身高 + 體重，長臂型球員（如 Gobert 類）會被低估。
- **擋拆**分布極度右偏（pr50 .39 / pr99 3.68，中鋒壟斷），目前直接線性映射，應改 log 或分位置。
- **對位**是同槽位配對（A 隊第 i 人守 B 隊第 i 人），沒有錯位與換防。
- **出手區域佔比是現代校準的。** PR50 基準是 2025-26 的 .483/.110/.407，
  所以湖人 2001-02 在模型裡不會投出當年的 .437/.378/.184。屬性算得到，時代打法算不到。
- 騎士 2015-16 的擋拆、湖人 2001-02 的無球/擋拆/盯防/協防都是手調值
  ——NBA hustle stats 自 2016-17 才完整，tracking 自 2013-14 才有。
- 防守 `PLUSMINUS` 會高估被藏起來的球員。
