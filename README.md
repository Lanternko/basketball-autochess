# Basketball Autochess — 數值模型與 OVR 計算器

目前版本與 GitHub 資料範圍見 [快照說明](docs/GITHUB_SNAPSHOT.md)。已接受的機率基準為 v47、輪替為 v49；最新完整 OVR 僅供診斷，尚未採用。

籃球自走棋的 possession 機率模型。這個 repo **只做數值層**：十六屬性 → 事件機率 → Monte Carlo。
沒有商店迴圈、連鎖、裝備——那些等數值地基固定之後再疊。
（`src/shop_constants.js` 只是把 TFT 的卡池／商店機率／升級曲線先抄成常數，沒有任何邏輯。）

設計文件在 [`docs/`](docs/)：[數值模型](docs/數值模型.md)、[隊伍卡表](docs/隊伍卡表.md)、[卡牌設計](docs/卡牌設計.md)、[卡表](docs/卡表.md)。
上游 GDD v0.1（子捷／Eve）不在 repo 裡。

## 架構

```
src/constants.js          錨點表、夾值、校準目標
src/shop_constants.js     卡池／商店機率／升級曲線（照抄 TFT，暫借的鷹架）
src/probability_model.js  屬性 -> possession 事件機率（四層分解）
src/simulation_engine.js  possession loop（傳球鏈）+ Monte Carlo
src/teams.js              五支真實隊 + PR50 基準隊 + 五小/雙塔測試隊（自動產生）
src/rng.js                種子亂數（可重現）
gen_teams.mjs             百分位 -> 屬性，產生 teams.js
gen_note.mjs              跑模擬，寫回 docs/隊伍卡表.md 的 GENERATED 區段
index.html                計算器 UI
```

參考 [Lanternko/Nine_innings](https://github.com/Lanternko/Nine_innings) 的四個部件：
錨點表逆推、分段線性插值當 S-curve、tanh 只用在修正因子、階層式機率分解最後 normalize。

「基礎屬性 → composite」的分層抄自 [zengm](https://github.com/zengm-games/zengm)（Basketball GM）。
**只抄結構，不抄常數**——zengm 的球員是自己隨機生成的，它的權重是為那個尺度校準的，
搬到「真實賽季百分位」尺度上會全錯而且不會報錯。

## 十六屬性

十三項由真實資料逆推：

| 屬性 | 逆推來源 |
|---|---|
| 三分 | `leaguedashplayershotlocations` Corner 3 + Above the Break 3 |
| 中投 | 同上，Mid-Range |
| 近射 | 同上，Restricted Area + In The Paint (Non-RA) |
| 罰球 | `FT_PCT`（低量用 log(FTA) 迴歸當先驗） |
| 切入 | `FTA/FGA` 與禁區出手佔比的合成百分位（**創造出手，不是終結**） |
| 傳球 | `AST_PCT` |
| 籃板 | `REB_PCT` |
| 盯防 | `leaguedashptdefend` DefenseCategory=**3 Pointers** 的 `PLUSMINUS` |
| 護框 | 同上，DefenseCategory=**Less Than 6Ft**（原名協防，2026-10-29 改名；程式欄位仍是 `help`） |
| 體力 | MPG |
| 肉體 | 身高 + 體重（0.45/0.55 標準化加權）。**臂展無公開資料** |
| 擋拆 | `SCREEN_ASSISTS` |
| 失誤 | `TOV/(FGA+0.44*FTA+**AST**+TOV)` 的反向百分位 |

三項手填——**沒有任何 box score 欄位對應得上**：

| 屬性 | 意義 | 為什麼分不出來 |
|---|---|---|
| 無球 | 跑動：繞掩護、空切、補位 | 不含定點投射威脅（那是 `SPACING_W` 從三分/中投另外算）。綁在一起就只能弄錯一邊：Draymond 跑動一流，但站在三分線外沒人理他 |
| 持球 | 自主拔投——不靠人餵也能製造出手並投進 | Curry 98 / Klay 62。兩人投籃百分位幾乎相同，一個是聯盟最強的自主拔投，一個是純接球投 |
| 破包夾 | 被兩個人夾住還能運出來或把球送出去 | Durant 切入 84 / 傳球 86 / 失誤 83 都不低，合成公式給他 78，但實際上被夾住就出不了球 |

這三欄的對齊目標是**真實 USG%**，逼近方式是有界座標下降 + 正則化，
但擬合器跑出沒有籃球意義的值時一律不採用（見「球權」一節）。

**十三項裡有十項只需要 box score、shot locations 或身高體重，1996-97 起零斷層**，
所以三個時代都能定錨。只有擋拆、盯防、護框三項依賴 tracking（2013-14 起）
或 hustle（2016-17 起）。

## 模型

錨點全部來自 NBA 真實分布（rotation player: G≥30, MPG≥20），`pr1→40 / pr50→70 / pr99→99`，
且**每名球員在自己那個賽季的母體內定錨**——2016 年的球員不會被現代三分潮稀釋。

```
L1  possession 大類    TOV / FOUL / SHOT
L3  命中（先算，因為出手選擇要看期望值）
      有效盯防 = 盯防 − 傳球品質下修 × 15
      有效護框 = 護框 − 傳球品質下修 × 12 + 空間稅 + (包夾率 − .16) × 45
      P(三分) = curve_3pt(三分) + 情境加成 × 聯盟三分命中 + pm(有效盯防)
      P(中投) = curve_mid(中投)                          + pm(盯防/護框各半 × 0.6)
      P(近射) = curve_short(近射) + 情境加成 × 聯盟近射命中 + pm(有效護框)
      P(罰球) = curve_ft(罰球)   ← 不受任何防守影響
L2  出手區域           p(zone) ∝ 半場佔比 × exp(ΔEV / EV_TEMP + 可及性 / ZONE_TEMP)
                       夾值互相衝突時走有界單體投影（water-filling），不是夾完再除總和
L4  未命中 -> 進攻籃板（延續同一 possession）-> 有機率直接補籃
```

`pm()` 是防守者的 `PLUSMINUS`（被他防守時對手命中率的絕對增減量），**直接相加**，
不轉成 tanh 乘數——因為它的原始語意就是命中率的增減量。

**情境加成用絕對增減量，不是乘數。** 這是後來改的：乘法會疊在本來就高的底上被放大。
近射 87 與 99 的曲線只差 .041，乘完同一組加成後差 .147——Durant 被推到 .878（夾值上限），
球權全流向他。改成 `curve(屬性) + (乘數 − 1) × 聯盟錨點` 之後，
隊友幫你創造出來的空檔，價值不再跟你本來多會投成正比，形式也跟防守端的 `pm()` 對齊了。

**肉體差 = 持球者肉體 − 對方全隊平均肉體。** 五小陣容因此被大個子克制。
肉體另有三個次要作用：隊伍籃板權重佔 30%、護框 +0.25×(肉體−70)、包夾威脅權重 0.25。

體力照 Nine_innings 的 `pitcherEffectiveness`：**削弱屬性，不加減機率**。

### 一次 possession 長什麼樣

不是「挑一個人出手」，是一條傳球鏈：

```
1. 誰把球帶起來    softmax(0.40×持球 + 0.30×傳球 + 0.15×切入 + 0.15×失誤)
2. 這球夠好嗎？    shootRate(EV)——門檻隨已傳球數遞減（傳越多次越急）
3. 傳得出去嗎？    passOpenRate(傳球者視野 + 隊友跑位 − 對位壓迫 − 包夾)
4. 被抄了嗎？      interceptRate
5. 誰接到          receiverWeights(接球投 EV + 創造力 + 無球 − 防守注意力)
6. 回到 2，最多 MAX_PASSES 次；次數用完或傳不出去 -> 勉強出手（forced）
```

第一手由**持球**決定而不是期望得分。用期望得分挑第一手會讓終結能力最強的人
變成控球後衛。切入權重壓到 0.15 是因為那一欄是「FTA/FGA + 禁區出手佔比」逆推的，
量的是終結方式，不是誰把球帶過半場。

**失誤要記進球權。** 真實 USG% 的分子是 `FGA + 0.44FTA + TOV`。
第一版的 `log.push` 排在兩條失誤路徑的 `break`/`continue` 之後，失誤從來沒被記進去，
Draymond 這種「傳球一流、投籃很差、失誤很多」的人因此被系統性低估。

### 中距離為什麼存在

純看期望值，中投（2 × .42 ≈ .84）永遠輸給禁區（2 × .58 ≈ 1.16）與三分（3 × .36 ≈ 1.09）。
NBA 就是這樣把中距離殺掉的。所以模型裡中投不是「另一種選擇」，而是**兩條路都被斷之後剩下的那條**：

```
可及性(三分) -= (有效盯防 − 70) × 0.45
可及性(近射) -= (有效護框 − 70) × 0.55
可及性(中投)  沒有人守
```

實測：對強防守中投佔比 **.199**，對弱防守只有 **.060**；
中投屬性 45→95 對弱防守值 +0.034，對強防守值 **+0.068**。

同一條可及性通道還接了三個來源：沒人能創造機會（自我否決）、勉強出手、空間不足。
**中距離是所有「路被堵住」的共同出口**，這是它在模型裡唯一的存在理由。

### 傳球必須影響得分，不能只重分配球權

第一版的傳球只影響誰出手——邊際價值量出來是 **+0.000**。
只重新分配球權的屬性等於不存在。

補上的機制不是直接加命中率，而是**下修對手的盯防與護框**：

```
傳球品質下修 -> 有效盯防 −15 點 / 有效護框 −12 點（滿檔）
```

15 和 12 這兩個數字**不是調出來的**，是從真實資料反推的：
聯盟三分接球投 .375 vs 持球投 .335，差 **.040**；
`CURVE_DEF_3PT` 的斜率是 .0027/點 → .040/.0027 ≈ **15 點**，
`CURVE_DEF_RIM` 是 .0034/點 → **12 點**。

走防守通道而不是直接加命中率，是因為好的傳球同時打開兩件事：**命中率**與**出手位置**
（`denyLong`/`denyShort` 一起縮小）。直接加命中率只有前者。

補完後 **+0.153**。

**中心化**：接球投的加成必須對「聯盟接球投比例」零和。命中率錨點本來就含真實比賽
裡的助攻球，只補不扣會補兩次。`LEAGUE_ASSISTED_RATE = .541` 是用不動點迭代校準出來的，
同一套紀律也用在勉強出手（`.185`）與包夾（`.16`）。

### 空間、無球、引力、包夾是四件事

一開始這四個概念全綁在「無球」一個屬性上，結果每一個都弄錯。現在分開：

| 概念 | 來源 | 量的是 | 合成 |
|---|---|---|---|
| **空間** | `0.75×三分 + 0.25×中投` | 不看他行不行 | 其他四人**平均**（每個不能投的人都送對手一個可以沉退的防守者） |
| **無球** | 手填 | 他會不會跑 | 其他四人平均 + 自己（空切、繞掩護接球三分） |
| **引力** | `max(0.60×三分+0.40×近射, 包夾威脅)` | 防守分掉多少注意力 | 其他四人**取 max**（防守只需分心顧最強的那一個） |
| **包夾威脅** | `0.5×(0.20三分+0.10中投+0.45近射+0.25肉體) + 0.5×(0.5持球+0.5切入)` | 不夾住他就會得分 | 隊友取 max |

引力取 max 而不是只看三分，是因為**兩個人被困在低位守 Shaq，外線一樣是空的**。
防守的注意力是一份，被拉出去或被吸進來都是同一份被用掉。
Shaq 的引力因此從 66 變成 88。

包夾威脅跟引力用不同的尺：引力量「會不會被拉出三分線」，
包夾量「不夾住他就會得分」——低位與禁區才是包夾的主場，
而且**必須自己製造得分**（Klay 從來不被包夾）。肉體直接進得分項，
因為投射效率百分位分不出 Shaq 與 Rick Fox（Fox 的近射 93 是 175 次的小樣本）。

### 包夾

```
包夾率 = .16 × (1 + tanh((自身威脅 − 基準) / 16) × 0.90)
             × (1 − tanh((破包夾 − 70) / 40) × 0.55)
基準  = 0.65 × 隊友最強威脅 + 0.35 × 70
被夾  -> 對手護框 +45 點（≈ 命中率 −.15）、傳球成功率 −40%、被抄機率 ×1.6
```

基準是「隊友最強」與「聯盟平均」的混合，不是純相對值。純相對值的話兩個怪物同隊會
互相抵消成誰都不用夾——但 2001-02 湖人是 Shaq 和 Kobe **都**被夾，剩下三個人被放空。

作用取**期望值**而不是逐次擲骰：一個吸引 30% 包夾的人，平均就承受 30% 的效果。
這樣 EV 評估是精確的，接球者選擇不必對包夾狀態再展開一層。

| | 包夾率 | 引力 |
|---|---|---|
| Durant | **.309**（勇士最高） | 91.2 |
| Curry | .099 | 93.6 |
| Shaq | **.244**（湖人最高） | 88.0 |
| Kobe | .148 | 82.9 |
| LeBron | .189 | 87.5 |
| Draymond | .032 | 63.0 |

「夾 Shaq，放 Kobe 打」是模型自己算出來的。Durant 則是反例：
威脅頂級但破包夾只有 52，所以對手可以放心夾他。

### 創造者必須是必需品

`evaluateLineup` 無條件替五個人各算一個期望得分，等於預設**球永遠送得到最好的位置**
——缺創造者不會被懲罰。補上的機制是**引力的鏡像**：

```
自主創造力 = 0.65×切入 + 0.35×傳球        ← 只看創造，不看投籃
依賴度     = clamp(0.5 + (70 − 自主創造力)/60, 0, 1)
             吃餅型 → 1、創造型 → 0、PR50 → 0.5
命中率加成 += tanh(隊友創造) × 0.14 × 依賴度 × 聯盟命中率
可及性     -= (70 − 隊友創造) × 依賴度 × {三分 0.20, 近射 0.30}
```

可及性那一項跟**防守否決同構**，只是來源在自己這邊：沒人能創造機會 = 自我否決。

實測：零創造者 → 一創造者值 **+0.181** 分/回合（同屬性總量），
第二個創造者的邊際值是 **−0.008**——一個大腦就夠，兩個是浪費終結與防守。
這正好是自走棋要的形狀。吃餅型對隊友創造力的敏感度 **+0.285** vs 創造型 **+0.136**。

**PR50 全隊時所有情境項都等於 70 → tanh = 0 → 加成 = 0，所以基準校準逐位不變。**

### 補籃

搶到進攻籃板之後有機率直接放回去，對手護框強就放不進去，只好拉出來重組：

```
補籃率 = .42 × (1 + tanh(肉體) × 0.30) × (1 − tanh(對手護框) × 0.55)
```

實測 **.421**（真實 NBA 40–45%）。加了這條之後禁區佔比會重複計算——
`LEAGUE_ZONE_SHARE.short = .483` 本來就含補籃，
所以 softmax 的先驗改用扣掉補籃的 `HALFCOURT_ZONE_SHARE = {.458, .115, .427}`，
`LEAGUE_ZONE_SHARE` 只留著當校準目標。

## 踩過的坑

**1. 兩分不能當成一個區。**
舊版只有 3PT / RIM 兩型態，中距離被砍掉，理由是中距離樣本兩端是假極值。
後果是系統性低估中距離時代——Kobe 2001-02 的投射被算成 41。
真正的解法不是砍，是**用出手數當先驗**（下一條）。

**2. 「沒出手」不等於「聯盟平均」。**
用經驗貝氏把命中率往聯盟均值收縮，會讓整季 1 次三分出手的 Shaq 拿到 pr 50。
統計上對，遊戲上錯——不投的人本來就比較差。改成先用 `log(出手數)` 迴歸命中率，
把迴歸線當先驗：Shaq 三分變 pr 8.1、Tristan Thompson（0 次出手）pr 0。

**3. Monte Carlo 要先累加次數再算比率。**
中投一場只有約 3 次出手，把每場的比率平均會讓投 0 次的場次貢獻 0，
中投命中率被壓低 4 個百分點。

**4. possession 的定義要對。**
進攻籃板**延續同一個 possession**，不是新的一次。一開始寫成每次出手都算一個回合，
結果先攻方因為多搶進攻籃板而多打，同隊對打產生 3.6% 的假優勢。

**5. TOV 曲線是「每次進攻機會」不是「每 possession」。**
一個 possession 平均有 ~1.18 次機會，複合後才是實際失誤率。

**6. 分類別的防守 PLUSMINUS 要收縮。**
`3 Pointers` 與 `Less Than 6Ft` 兩類的原始 pr1/pr99 到了 ±.19 與 ±.21，
但那是樣本雜訊灌水的——每人每場只守約 4 次三分出手。直接用會讓 pr99 防守者
把對手三分從 .364 砍到 .184。以 `Overall` 類別（樣本大得多，±.08）反推收縮係數。

**7. EV_TEMP 太小會讓屬性升高反而變弱。**
混合期望值對某區 EV 的偏導是 `w_z × (1 + (ev_z − 混合均值)/T)`，
當 `T` 小於「最差區與均值的差距」時是負的——中投練高只是讓你多投爛球。
實測 0.55 是臨界值，取 0.60。單調性測試會抓到這個。

**8. 夾值互相衝突時不能夾完再除總和。**
三分上限 .58、中投下限 .02、近射下限 .30 相加是 .90 ≠ 1，三個邊界是互相不可行的。
夾完再正規化會把三分推到 .644（超出上限）；反覆「夾了再除」會收斂到 .594，還是超出。
正解是**有界單體投影**：把差額只分配給還有餘裕的區。

**9. 任何只施加在部分出手上的加減，都必須對那個子集合的聯盟比例零和。**
命中率與出手佔比的錨點本來就含真實比賽裡的助攻球、勉強出手、被包夾的球，
只補不扣（或只扣不補）會算兩次。接球投 `.541`、勉強出手 `.185`、包夾 `.16`
三個中心化常數都是用不動點迭代校準的。

**10. 乘法情境加成會在高底上被放大。**
近射曲線 87 → .625、99 → .666，只差 .041；乘完同一組情境加成後變成 .731 vs .878，
而 .878 剛好頂到夾值上限。改成加法（`curve + (乘數−1) × 聯盟錨點`）之後才對。

**11. 失誤沒有被記進球權。**
`log.push` 排在兩條失誤路徑的 `break`/`continue` 之後。真實 USG% 的分子含 TOV，
少記的話「傳球一流、投籃很差、失誤很多」的球員被系統性低估。

**12. 合成公式不是萬能的。**
破包夾原本用 切入/傳球/無球/失誤 合成。Durant 這幾項分別是 84/86/83，
合成給他 78——但他被夾住就出不了球。有些東西 box score 就是沒有欄位，
硬合成只是把錯誤藏進一個看起來很客觀的公式裡。

- **臂展沒有公開資料。** 肉體只用身高 + 體重，長臂型球員（如 Gobert 類）會被低估。
- **三分區沒有細分。** 底角與弧頂共用一條曲線，超遠射程拿不到額外信用。
- **擋拆**分布極度右偏（pr50 .39 / pr99 3.68，中鋒壟斷），目前直接線性映射，應改 log 或分位置。
- **對位**是同槽位配對（A 隊第 i 人守 B 隊第 i 人），沒有錯位與換防。
- **出手區域佔比是現代校準的。** PR50 基準是 2025-26 的 .483/.110/.407，
  所以湖人 2001-02 在模型裡不會投出當年的 .437/.378/.184。屬性算得到，時代打法算不到。
- **手填三欄（無球/持球/破包夾）沒有 API 逆推。** 對齊目標是真實 USG%，
  但那是輸出對齊，不是獨立來源。
- 騎士 2015-16 的擋拆、湖人 2001-02 的擋拆/盯防/護框都是手調值
  ——NBA hustle stats 自 2016-17 才完整，tracking 自 2013-14 才有。
- 防守 `PLUSMINUS` 會高估被藏起來的球員。
- **模型裡沒有教練。** 出手分配純由期望得分驅動，沒有任何角色配額，
  所以像 Durant 這種「屬性全面頂級但真實出手受戰術限制」的球員會被高估。
