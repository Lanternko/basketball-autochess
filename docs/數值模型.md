## 0. 已拍板的前提

從 GDD v0.1 之後追加確定的四項：

1. **失敗條件**：一局約 10 場。兩案——遞增扣血（5/6/7…15，總血 100）或季賽戰績決定四強再打淘汰。
2. **單場結構**：短局、回合制。每回合數值比拼，數值高者佔優，但**是否得分走機率**。搶籃板、傳球、抄截、投射都是獨立機率事件。
3. **受傷不跨場**：小傷扣體力、大傷數值打折或強制換替補。GDD §5「湊不齊五人」與 §14「重傷復健區」作廢，需回頭改寫。
4. **屬性擴充到八個**：原六屬性 + 無球 + 擋拆。

> [!WARNING]
> **遞增扣血案的算術問題**
> 5 起每場 +1，10 場全輸累計只有 **95**（5..14），總血 100 撐得過全敗，血條永遠不會歸零。
> TFT 的遞增扣血有效是因為一局 30+ 回合且旁邊對手真的在被淘汰，10 場 PVE 兩個條件都不成立。
> **建議選季賽 → 四強案。** AI 對 AI 的比賽不用跑引擎，用隊伍強度抽勝負即可，只有玩家參與的那場跑完整結算。

## 1. 參考架構：Lanternko/Nine_innings

三個 repo 中 [Nine_innings](https://github.com/Lanternko/Nine_innings) 才是完整模型。
（`Baseball_OVR_calculator` 只有設計目標無公式；`Baseball` 是加法係數的粗版，其 `gameLogic.js` fallback 用連續 if 比對單一亂數、機率未正規化，**不要抄那段**。）

關鍵檔案：`docs/backend/app/core/game_constants.py`、`probability_model.py`

### 四個可移植部件

**① 錨點表逆推**

```python
LEAGUE_BENCHMARKS = {'xBA': {'pr1':0.200,'pr50':0.250,'pr99':0.330}, ...}
ATTRIBUTE_MAPPING_POINTS = {'pr1':40, 'pr50':70, 'pr99':99}
SOFT_CAP_ATTRIBUTE_VALUE = 150.0   # 屬性可破 99，錨點延伸到 150
```

**②「S-curve」= 錨點列表 + 分段線性插值**（不是 sigmoid）

```python
HR_S_CURVE_POW_ANCHORS = [(0,0.0005),(40,0.0067),(70,0.0333),(99,0.0580),(130,0.087),(150,0.110)]
```

手調任何一段不影響其他段，比擬合解析曲線好維護。**直接照抄這個做法。**

**③ tanh 只用在修正因子，不用在主率**

```python
eff = tanh((attr - 70) / scale)            # -1 .. 1
p_hr = base_hr(POW) * (1 + eff_eye*0.12) * (1 + eff_hit*0.18)
```

主率走錨點插值，次要影響走 tanh 乘數。兩層分工。

**④ 階層式機率分解，最後 normalize**

```
K / BB / HBP / HR 各自算 → 夾值
剩餘 = BIP → 用 BABIP(HIT) 拆 hit / out
hit 再用 POW+HIT 拆 1B / 2B
全部 clamp → normalize 到總和 1.0
```

每層是條件機率、有獨立語意，調某層不污染其他層。**比「全部並列後 normalize」好，籃球照這個結構。**

## 2. 十四屬性與定錨分野

> [!NOTE]
> **資料基準**
> NBA.com `leaguedashplayershotlocations`（**1996-97 起每季都有**）+ tracking（hustle / CatchShoot / ptdefend / biostats）。
> 母體：**rotation player = G ≥ 30 且 MPG ≥ 20**。拉取日 2026-09-05。

第二輪修訂：速度砍掉換成肉體、體能改叫體力、防守分化成盯防與協防（2026-10-29 改名護框：它只量也只管籃下 6 呎內，見下方註）。
第三輪修訂：**投射拆成三分 / 中投 / 近射，切入改成「創造出手」而非終結。**

| 屬性 | 逆推來源 | 品質 |
|---|---|---|
| **三分** | shot locations · Corner 3 + Above the Break 3 的 FG% | 好 |
| **中投** | shot locations · Mid-Range 的 FG% | 好 |
| **近射** | shot locations · Restricted Area + In The Paint 的 FG% | 好 |
| **切入** | `0.5×z(FTA/FGA) + 0.5×z(禁區出手佔比)` | 好（全時代可得） |
| **傳球** | `AST_PCT` | 好（全時代可得） |
| **罰球** | `FT_PCT`（低量用 log(FTA) 迴歸當先驗） | 好（全時代可得） |
| **失誤** | `TOV/(FGA+0.44FTA+**AST**+TOV)` 反轉 | 好（分母含助攻，見下） |
| 籃板 | `REB_PCT`（分位置） | 好 |
| 盯防 | `leaguedashptdefend` **DefenseCategory=3 Pointers** 的 `PLUSMINUS` | 好（需收縮） |
| 護框 | 同上，**DefenseCategory=Less Than 6Ft** | 好（需收縮）。原名協防，2026-10-29 改名；程式欄位仍是 `help` |
| 體力 | MPG | 半逆推 |
| 肉體 | `leaguedashplayerbiostats` 的身高 + 體重 | 好（缺臂展） |
| 無球 | `CATCH_SHOOT_FG3A` | 半逆推 |
| 擋拆 | `SCREEN_ASSISTS` | 可用（右偏） |

### 為什麼拆三圍投籃

v0.2 只有三分與兩分，中距離被砍掉，理由是「中距離資料兩端是假極值」。
那個理由對 2025-26 成立，套到 2001-02 就等於**抹掉那個時代的主要得分方式**：

| 賽季 | 近射 | 中投 | 三分 |
|---|---|---|---|
| 2001-02 | .437 | **.378** | .184 |
| 2015-16 | .466 | .252 | .282 |
| 2016-17 | .455 | .230 | .315 |
| 2025-26 | .483 | **.110** | .407 |

Kobe 2001-02 的中投 pr 68.6、近射 pr 90.5——他的價值本來就在被砍掉的那一區。

而且 `leaguedashplayershotlocations` **1996-97 起每季都有**，不像 tracking（2013-14 起）
或 hustle（2016-17 起）。拆成三圍反而**消除**了時代斷層，不是增加。

> [!IMPORTANT]
> **假極值的正解不是砍，是用出手數當先驗**
> 用經驗貝氏往聯盟均值收縮，會讓整季只出手 1 次三分的 Shaq 拿到 **pr 50.5**。
> 統計上對，遊戲上錯——不投的人本來就比較差。
>
> 改成先用 `log(出手數)` 迴歸命中率，把**迴歸線**當先驗（出手少的人先驗就低）：
> Shaq 三分 **pr 8.1**、Tristan Thompson（整季 0 次三分）**pr 0**、Hartenstein **pr 4.8**。

### 切入改成「創造」而非「終結」

v0.2 的切入用 `DRIVE_FG_PCT`，那是終結能力——但近射屬性已經涵蓋終結了。
改成 `FTA/FGA` 與禁區出手佔比的合成：**能不能把球帶進禁區、能不能造犯規**。

兩個好處：語意不重複；`DRIVES` 是 2013-14 起才有的 tracking，
FTA 與出手位置則是全時代可得，湖人 2001-02 的切入不再需要手調。

### 肉體的定義與作用

```
肉體 = 0.45 × z(身高) + 0.55 × z(體重)，再取百分位
```

**臂展沒有公開資料**（僅選秀體測有，且不是每人都有），所以長臂型球員會被低估。

| 作用 | 位置 | 強度 |
|---|---|---|
| **禁區優勢**（主要） | 近射命中乘數 | `tanh((我的肉體 − 對方全隊平均肉體)/45) × 0.18` |
| 出手選擇 | L2 可及性把選擇往禁區拉 | 12 分 |
| 籃板 | 隊伍籃板 = 0.7×籃板 + 0.3×肉體 | 0.30 |
| 護框 | 護框 += 0.25 × (肉體 − 70) | 0.25 |

**比的是「我 vs 對方全隊平均」**，這是「五小被歐尼爾克制」的機制來源。

### 防守分化

盯防對應三分、護框對應禁區，正好對上 tracking 的 `DefenseCategory` 分類，不需要自己編。
中投由兩者各半負責，再乘 0.6——中距離是最難干擾的一區。

> [!WARNING]
> **分類別的 PLUSMINUS 必須收縮**
> 原始分布寬度被樣本雜訊灌水——每人每場只守約 4 次三分出手、3–6 次禁區出手：
>
> | 類別 | pr1 | pr50 | pr99 |
> |---|---|---|---|
> | 3 Pointers | −.192 | −.007 | +.171 |
> | Less Than 6Ft | −.214 | −.011 | +.208 |
> | **Overall（參照）** | **−.076** | **+.003** | **+.086** |
>
> 直接用會讓 pr99 防守者把對手三分從 .364 砍到 **.184**，遊戲直接爆掉。
> 以 Overall（樣本大得多）當真實技術尺度反推收縮：盯防 ±.085、護框 ±.105
> （護框的真實效果本來就比守三分大）。

## 4. 四層 possession 分解

```
L1  possession 大類
    TOV    ← 持球者 失誤 vs 對位 盯防
    FOUL   ← 持球者 切入
    SHOT   ← 剩餘

L3  命中（先算，因為出手選擇要看期望值）
    P(三分) = curve_3pt(三分) × (1 + tanh(隊友無球)) + pm(盯防)
    P(中投) = curve_mid(中投)                       + pm(盯防/護框各半 × 0.6)
    P(近射) = curve_short(近射) × (1 + tanh(隊友擋拆)) × (1 + tanh(肉體差)) + pm(護框)

    肉體差 = 持球者肉體 − 對方全隊平均肉體      ← 五小被大個子克制的來源

L2  出手區域 (given SHOT)
    p(zone) ∝ 聯盟佔比 × exp( ΔEV / 0.60 + 可及性 / 30 )

    ΔEV    = 這區的期望得分 − PR50 基準（值不值得投）
    可及性  = 拿不拿得到這種出手：
             三分 += (隊友無球 − 70) × 0.35 − (盯防 − 70) × 0.45
             中投 += (切入 − 70) × 0.15          ← 沒有人守
             近射 += (隊友擋拆 − 70) × 0.30 + (切入 − 70) × 0.55
                     + 肉體優勢 × 12 − (護框 − 70) × 0.55

L4  未命中 → 進攻籃板（延續同一 possession）

每層 clamp → normalize
```

> [!NOTE]
> **防守項是加法不是乘法**
> 因為 `PLUSMINUS` 的原始語意就是「對手命中率的絕對增減量」，直接加即可，不需要轉成 tanh 乘數。
> 進攻側的無球／擋拆／肉體沒有這種現成量表，才走 tanh 乘數。兩側形式不對稱是**刻意的**。

用戶要求的四條映射全部落在 L2/L3 的**修正項**位置，天然不相乘：

- 隊友無球 → 增加三分
- 擋拆 → 增加近射
- 盯防 → 限制三分
- 護框 → 克制近射

### 中距離為什麼存在

純看期望值，中投（2 × .42 ≈ .84）永遠輸給近射（2 × .58 ≈ 1.16）與三分（3 × .36 ≈ 1.09）。
NBA 就是這樣把中距離殺掉的。所以模型裡中投不是「另一種選擇」，
而是**兩條路都被斷之後剩下的那條**——只有中投的可及性不含防守否決項。

| 對手盯防/護框 | 近射 | 中投 | 三分 | 每回合得分 |
|---|---|---|---|---|
| 40 / 40 | .501 | .052 | .447 | 1.370 |
| 70 / 70 | .475 | .110 | .415 | 1.161 |
| 99 / 99 | .421 | .215 | .364 | 0.945 |

中投屬性的邊際價值也跟著分化：45→95 對弱防守只值 **+0.003** 分/回合，
對強防守值 **+0.028**。這正是「季後賽需要中距離」那個說法的量化版本。

> [!CAUTION]
> **EV_TEMP 太小會讓屬性升高反而變弱**
> 混合期望值對某區 EV 的偏導是 `w_z × (1 + (ev_z − 混合均值)/T)`，
> 當 `T` 小於「最差區與均值的差距」時是**負的**——中投練高只是讓你多投爛球。
> 實測 T = 0.55 是臨界值，取 0.60。單調性測試會抓到這個。

### 誰出手：出手品質搜尋

v0.2 用靜態 usage 權重（`((投射+切入)/2)^1.6`），跟實際出手品質脫鉤——
Durant 期望得分 1.385 只拿 25.9% 球權，Iguodala 1.263 卻拿 19.5%，
Shaq 是全隊最好的出手選擇卻只有 20.7%。

現在每次進攻機會都算五個人各自持球的完整機率分布，再依期望得分 softmax 抽：

```
usage_i ∝ exp( (期望得分_i + 1.10 × 創造力_i / 100) / 0.22 )
創造力 = 0.45×三分 + 0.30×中投 + 0.10×近射 + 0.15×切入 − 0.20×(無球 − 70)
最後夾在 8.5%–34.5%（NBA 真實範圍）再正規化
```

**創造力偏重跳投而非近射**，因為中鋒的近射 98 多半是接球放進去——那是別人創造的。
用「三項最高值」當創造力會把吃餅中鋒誤判成創造者（實測 Shaq 會衝到 42.4% 球權）。
**減無球**是為了分開持球創造者與定點射手：兩者效率可能一樣，但球不會交給後者。

成本是每次機會算五次而非一次，單場約 470 次呼叫——可接受。


## 5. 體力

照抄 `pitcherEffectiveness` 的位置與作法：

```
effectiveness = 0.7 .. 1.0   （依剩餘體能）
進攻屬性 * effectiveness → 再進機率模型
```

**是削弱屬性，不是加減機率。** 這樣疲勞的效果會自然穿透所有下游事件。
GDD §9「關鍵先生」（末節投射大幅上升）就是在後段給一個反向 effectiveness 加成。

小傷 = 扣體力（等於提早進入低 effectiveness 區間）。
大傷 = 數值直接打折，或強制換替補。

## 6. 逆推流程

### 6.1 固定情境逆推（**必須先決定，事後補很痛**）

籃球的個人成績受隊友汙染：一個射手的 3P% 同時取決於自己的投射、隊友的無球、對手的防守。多組 `(投射, 無球)` 會產生同樣的 3P%，最佳化器會收斂到隨機的其中一組——**可辨識性問題**。

對策：逆推某球員時，把他放進一支標準化的 **PR50 五人隊**，對上 **PR50 防守**，只搜索他自己的屬性，目標是複製他的真實 per-possession 率。隊友效應被常數化，解唯一。

### 6.2 三階段隨機搜索（照抄 Nine_innings）

```
階段一：1500 次迭代 x 15 季  → 取 top 100
階段二：每候選 100 次 x 40 季 → 取 top 15
階段三：200 季最終驗證

ERROR_WEIGHTS: 對主要成績加權（棒球版 BA 1.5 / OBP 1.8 / SLG 1.5 / HR 2.0）
DEVIATION_PENALTY_WEIGHT: 0.01 → 0.075 三階段遞增
```

> [!IMPORTANT]
> **錨點懲罰是關鍵細節**
> `DEVIATION_PENALTY_WEIGHT` 遞增，防止最佳化找到「輸出數字對、但屬性組合荒謬」的解。
> 籃球版誤差權重初擬：eFG% 1.8 / 3P% 1.5 / RIM FG% 1.5 / REB% 1.2 / TOV% 0.8。

### 實作時修正的四個模型錯誤

**① 兩分曲線不能用 `DRIVE_FG_PCT` 當輸出**
屬性排序由 DRIVE_FG_PCT 百分位決定沒問題，但 MID 砍掉後這條曲線的**輸出**代表所有兩分出手（含空切、補籃、灌籃），league median 是 **2P% 的 .537**，不是突破的 .492。用錯讓 eFG% 系統性偏低 8%。§3.1 要標清楚「排序來源」與「輸出量表」是兩件事。

**② possession 的定義**
進攻籃板**延續同一個 possession**，不是新的一次。原本每次出手算一回合，導致先攻方因多搶進攻籃板而多打，同隊對打出現 **3.6% 的假優勢**。修正後 49.5%，而且每回合得分才能跟 NBA 的 1.15 直接比較。

**③ TOV 曲線的分母**
是「每次進攻機會」不是「每 possession」。一個 possession 平均 ~1.18 次機會，複合後才是實際失誤率，錨點要先除以該係數。

**④ 分類別的防守 PLUSMINUS 要收縮**（見 §2「防守分化」）
直接用原始分布會讓 pr99 防守者把對手三分砍到 .184。以 Overall 類別當真實技術尺度反推收縮。

### 另外兩個要調的參數

- **usage 指數**：純指數會讓 SGA 衝到 49.2% 持球（NBA 上限 ~35%），Draymond 掉到 2.3%（下限 ~10%）。改成指數 1.6 + 與均勻分布混合 20%，才落回真實區間（最高 31.1%、最低 10.3%）。
- **`SHOT_TYPE_TEMP`**：22 太敏感，OKC 的 3PA 佔比掉到 .200（真實範圍 .32–.52）。改 38。

包夾率的基準是「隊友最強威脅 × 0.65 + 聯盟平均 × 0.35」，不是純相對值——
純相對值的話兩個怪物同隊會互相抵消成誰都不用夾，但 2001-02 湖人是
Shaq（.244）和 Kobe（.148）**都**被夾，剩下三個人（.029–.055）被放空。

### 這一輪修掉的三個系統性錯誤

**1. 乘法情境加成在高底上被放大。**
近射曲線 87 → .625、99 → .666 只差 .041，乘完同一組情境加成後變成 .731 vs .878，
而 .878 剛好頂到夾值上限，球權於是全流向 Durant。改成
`curve(屬性) + (乘數 − 1) × 聯盟錨點`——跟防守端 `pm()` 的加法形式對齊。

**2. 夾值互相衝突時不能夾完再除總和。**
三分上限 .58 + 中投下限 .02 + 近射下限 .30 = .90 ≠ 1，三個邊界互相不可行。
夾完再正規化把三分推到 .644；反覆「夾了再除」收斂到 .594，還是超出。
正解是**有界單體投影**，把差額只分配給還有餘裕的區。

**3. 失誤沒有被記進球權。**
`log.push` 排在兩條失誤路徑的 `break`/`continue` 之後。真實 USG% 的分子是
`FGA + 0.44FTA + TOV`，少記的話「傳球一流、投籃很差、失誤很多」的球員
被系統性低估。

### 中心化紀律推廣到三處

任何只施加在**部分出手**上的加減，都必須對那個子集合的聯盟比例零和——
命中率與出手佔比的錨點本來就含真實比賽裡的那些球。
`LEAGUE_ASSISTED_RATE = .541`、`LEAGUE_FORCED_RATE = .185`、
`LEAGUE_DOUBLE_RATE = .16` 三個常數都是用不動點迭代校準的。

### 順帶對上的觀測量

沒有直接校準，但跟真實值對得上：被助攻比例 .541（真實 .54）、
進攻籃板率 .278（真實 .27）、補籃佔進攻籃板 .421（真實 .40–.45）。


## 8. 第一個里程碑

> **先做「籃球 OVR 計算器」網頁，跟 Nine_innings 同形。**
> 輸入兩隊各五人的八屬性 → 跑 1000 場 → 輸出平均比分、勝率、事件分布（出手分佈／命中率／籃板／失誤）。

沒有商店、卡牌、連鎖、裝備、美術。它單獨驗證整個設計最不確定的那塊：八屬性 → possession 事件機率，跑出來**像不像籃球**、以及**變異數可不可接受**。

這一步比 GDD §20 的垂直切片更前面、更便宜。做完數值地基固定，後面商店／連鎖／裝備都是在確定地基上疊標準自走棋模組。**跳過這步就往上疊，之後每次調數值都會震動整個系統。**

檔案切法沿用 Nine_innings：

```
constants.js        錨點表、夾值上下限
probability_model.js  屬性 → possession 事件機率
simulation_engine.js  possession loop + Monte Carlo
optimization.js       三階段逆推搜索
```

> [!TIP]
> **測試資料已備妥**
> 三支隊伍 × 五人的完整八屬性卡表見 [隊伍卡表 v0.1](隊伍卡表.md)（勇士 2016-17 / 騎士 2015-16 / 雷霆 2025-26），全部由 tracking 數據逆推、各自賽季內定錨。可直接當 OVR 計算器的第一批輸入。
