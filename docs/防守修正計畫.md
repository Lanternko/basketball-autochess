2026-10-12。目標：讓全聯盟、球隊與不同場上陣容的防守表現都能合理重現，並讓逆推能力具備可解釋性。第一批已實作為獨立 `nba-defense-v1` 版本，保留原引擎基準；完整防守與資料外驗證仍待後續階段。

## A 收尾與 B1 資料準備結果

最新指令的四項工作已完成，停下回報，見 [收尾報告](../reports/defense-b1/closeout.md)。v1補齊seed20261012–31；採用主判準為二十seed的淨勝分去均值RMSE、相關、SD比和每分淨勝分勝場斜率，勝場MAE只列示。所有指標提供seed區塊bootstrap SE及成對版本差區間。

經驗耗時／獨立時鐘違例另立實驗fork，完整賽季校準。二十seed球權代理偏差+0.141，但效率偏差+3.109、TOV偏差−2.142，沒有取代v1或調整TOV係數。原版、v1、A3引擎保留。真實違例0.674／隊／場；原v1時鐘略過的直接抄截機率約0.11／場，只能解釋小部分STL缺口。

真實與v1共同1227場變異拆解：殘差SD14.027對17.557；分數平方差約28%來自單回合分布、32%來自非球權同場共變異、球權項合計−3.5%，其餘43%含隊內序列／對戰異質性，不能當成唯一比分耦合因果。事件已確認三分加罰四分回合真實314、v1模擬3053（1227／1230場）；後續B2先將未進球投籃犯規與命中加罰分成各自可觀測的約束，再檢查比分與輪替耦合，不直接限制分差。

B1只有資料準備：1220場五人／分鐘驗證通過，嚴格排除回合歸屬與來源計數問題後1188場、38623個區段可用。產出細分出手區、四要素、回合及每位球員樣本，沒有估計防守屬性、修改OVR或把真實換人時點餵入模擬。B1估計、B2/B3實作和B4資料外驗證仍待後續指令；以上採用判準取代前文的歷史期望勝場條件。

## 第三批結果：事件分布與B1離線估計

五項工作已完成後停下，詳見 [第三批報告](../reports/defense-third/closeout.md)與 [B1離線表](../reports/defense-third/offline-model.md)。原版、v1、A與前批經驗時鐘引擎保持原樣。新犯規／失誤機制放在獨立第三批fork，各項能獨立關閉；類別目標直接來自逐球資料，沒有球隊ID／勝場或OVR補丁。

完整二十seed候選的效率、球權、TOV、STL與違例率通過；但SD比0.699低於v1的0.722，2分回合少0.558個百分點、3分多0.815個百分點，FTR偏高，沒有取代v1。FG%／3P%絕對偏差分別多約0.020／0.025個百分點，按「不退步」點估計門檻未過，但不能視為顯著惡化。每個採用判準與成對95%區間均保留。

先前SD比0.722→0.666主要下降在「取消能力相依的耗時撞限，改獨立違例」這一步：0.715→0.681，成對差區間−0.0625～−0.0023；換經驗耗時再降到0.666，但該步區間跨零。這是開關路徑結果，不能把所有被移除的能力差異都當成正確防守訊號。

分鐘目標改為賽季MPG後，淨勝分相關0.821→0.798，差異區間−0.0471～−0.0005；SD比、殘差SD和單隊得分隊內變異沒有清楚差異。保留逐場出賽者、先發與替補排序，以及全季卡片，因此只支持「逐場分鐘會提高一些相關」的診斷，不支持其灌高單場變異的說法。

犯規分布修正讓單回合變異到1.430，先前單回合變異差剩約12%；非球權同場共變異差卻擴大到169%，序列／異質性餘項剩61%。均為相對前批單seed差值的分數平方比例，不是SD分攤或因果證明。比分相依輪替／共變異與球隊節奏仍分別留給B2／B3。

B1用兩隊都在各自前41場的574個嚴格場次訓練，後41場614個場次測試；避免同一場進攻／防守區段落在兩邊。現行訊號重建為前41追蹤版本，模型box先驗也只用訓練場，CV每折重算先驗。五項RMSE有四項顯著改善，但三分相關仍為負、活球失誤改善區間跨零；FA模型保留零回合罰球換人區段，尚屬條件區段計數，尚未回歸到犯規當下陣容。離線模型未接引擎，也尚未完成跨賽季或模型重訓不確定性驗證。

## 第一批實作

- 新增1230份官方box score與30隊進階資料，保存先發位置、逐場秒數、來源網址與雜湊。CDN比分與既有官方逐場紀錄不一致時，退回NBA場次頁面的box score；驗證兩隊球員總得分與五人分鐘。
- `minute_budget.js` 建立正規時間曝光控制，按0.1秒分配240球員分鐘。實際OT分鐘先按比例規格化，模擬OT另計。合成換人不是觀測陣容，會影響疲勞分布；診斷模式允許非死球換人並停用犯滿，不能把其差異單獨解釋成分鐘因果效果。
- `defense_game.js` 保留舊條件的逐場比分相同路徑，另加失誤與抄截分類、獨立壓迫訊號、分區投籃與預期命中記帳。只改分類時比分、總失誤、時間及延長賽完全相同；完整反擊狀態尚未加入。
- 修正投籃犯規的條件機率：真實FG%已排除犯規投失，不能先用該FG%抽命中再排除一次。使用可逆的條件機率變換，避免記帳FG%被灌高。
- 分離三分／近射的直接情境係數；以正常輪替、場內疲勞及六犯離場條件校準。出手量權重使用在隊整季量測；抄截率先驗使用整季聯盟量測，沒有球隊ID或勝場補丁。
- `NBA_DEFENSE_V1` 使用官方先發與逐場分鐘軟目標、正常犯滿與死球／節間輪替。固定曝光控制與正式回溯版本分開，不混用診斷排程結果。

執行 `npm run simulate:season:defense`。機制拆解見 `reports/defense-validation.md`，四seed正常輪替與控制比較見 `reports/defense-stability.md`。新seed只驗證抽樣穩定性，沒有完成資料外預測驗證。六項已知結構限制以下以原版本為診斷起點；新版本已分離失誤壓迫，但區域防守口徑、真實陣容責任與反擊仍未完成。

## 已知偏差與尚待確認的原因

既有診斷見 `reports/season-diagnostics.md`。雷霆模擬46勝、真實64勝，場均失分多10.48分。全聯盟命中率共同偏高，因此不能把所有差額都解釋成雷霆球員的防守評分不足。

程式可確認的結構限制：

- `onBall` 來自三分防守命中率差，但同時控制投射干擾、傳球可及性、攔截及持球失誤壓迫。這些能力缺少各自的觀測約束。
- `help` 來自6呎內防守，但 `short` 合併籃下與其他油漆區出手；兩者的區域與機會母體不一致。
- 同槽位球員固定對位、協防取加權前兩人，沒有依持球／出手角色選擇防守責任。
- 引擎只將傳球攔截記為STL；持球失誤沒有活球／死球及防守者歸屬拆解，也沒有完整反擊狀態。
- 火鍋只是已判定投失的分解，不是獨立降低命中率的機制。增加記帳火鍋不能自動增加防守收益；重複降低命中率也可能重複計算。
- 輪替分鐘與先發／位置為推估，未鎖成真實陣容區段。

需用控制實驗確認的原因：全局投射偏高是否來自情境加成、出手選擇與球權選擇的疊加；防守收縮是否過強；不同陣容的有效防守權重是否錯配。不能預先把上述候選原因當成已證實結論。

## 第一階段：固定比較口徑與建立誤差分解

1. 保留目前基準、seed、來源與程式雜湊，所有新版本另列。
2. 建立診斷用逐場分鐘模式及官方先發／位置；若只有總分鐘，不能稱為已重現真實換人時段。犯滿、延長賽與零分鐘球員另有明確處理規則。
3. 實際回合與模擬回合使用一致定義：進攻籃板延續球權，罰球、節末及技術犯規不任意增加回合。資料不足時同時列出估計值與限制。
4. 同時比較每百回合失分、對手分區出手／命中、迫使失誤、活球失誤、罰球率及防守籃板率。
5. 分別關閉或替換情境加成、機會選擇及輪替，辨識全局偏差來源；不直接對雷霆加特殊係數。

## 第二階段：補最少必要資料與事件機制

優先資料與用途：

| 資料 | 用途 | 限制／防止誤用 |
|---|---|---|
| 球隊對手分區出手與命中 | 拆出限制出手機會與降低命中率 | 僅作校準／比較目標，不直接當比賽答案 |
| 球員STL、BLK、PF、DREB與分鐘 | 約束壓迫、護框記帳、犯規和收尾 | 比率需分母及機會曝光，不能只用每場次數 |
| 逐球事件、換人與先發 | 活球／死球失誤、場上五人、on/off及回合 | 需驗證事件順序、替換、技術犯規與缺漏 |
| 分區防守命中率及被防守出手數 | 命中干擾訊號與樣本收縮 | 不等於完整個人防守能力，也不直接等於換隊效果 |
| 可取得的撥球、干擾出手及對手空檔比例 | 補充防守活動與機會訊號 | 定義不同；撥球不能一律視為抄截，干擾次數不能直接視為效果 |

資料先確認可取得且完整，再決定納入。高階單一總分不是必要前提；個人DefRtg及原始正負值不直接映射成盯防／協防能力。

機制最小修改：

1. 將既有失誤合理拆成活球／死球，為可歸屬的抄截指定防守者；再校準壓迫對總失誤的影響，避免新增STL時重複增加TOV。
2. 分離投射干擾與製造失誤的內部訊號，不必先增加卡面屬性。
3. 對齊近射防守與出手區域；依角色及陣容分配直接防守與護框責任，先採可驗證的抽象機會模型。
4. 讓活球失誤有明確反擊狀態；其發生率、耗時與效率分開驗證。
5. 火鍋與防守命中率使用一致的事件分解，保持一次出手只有一次結果，避免重複防守加成。

## 第三階段：校準少量可解釋參數

先修正全局基準與進攻情境重複信用，再調整防守權重、樣本收縮、壓迫／犯規及機會分配。每批只改一組機制，保存前後比較；低樣本資料收縮，未知量明確標註。30隊共同適用，不以球隊ID或真實勝場作機率輸入。

如果全局平均對齊而強弱防守仍分不開，繼續檢查個人能力與陣容組合；不能用全局命中率補丁宣稱已解決此問題。

## 第四階段：驗證通過的含義

- 程式正確性：比分、五人分鐘、球權、失誤／抄截、投失／火鍋、籃板與正負值守恆。
- 統計合理性：全聯盟均值、30隊誤差與防守排序、對手出手分布及不同陣容區段同時比較；得分接近不能掩蓋回合或命中率錯誤。
- 機制合理性：提升干擾、壓迫、護框或籃板時，合理改善對應結果，並記錄模型中的代價；檢查是否因出手選擇產生反向效果。
- 穩定性：多組seed給出模擬分布與抽樣誤差；新seed僅驗證隨機穩定性。
- 資料外有效性：按時間切分歷史資料，建卡和收縮先驗只能用截止日前資料，調參與測試分開。現有使用整季能力的2025–26回溯報告不能藉由換seed變成獨立預測驗證。
- 逐批採用：事先固定評估指標與容許誤差，再看訓練與測試結果；改善多隊的結構指標才支持採用，雷霆勝場接近64不單獨構成成功。

球員OVR待機制與曝光穩定後，再使用同陣容比較或正則化調整正負值輔助檢查。原始正負值殘差不能直接換算成OVR修正或某人帶來幾場勝差。
