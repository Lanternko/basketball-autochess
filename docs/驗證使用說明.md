# 個人統計與 36 分鐘等效驗證

## 執行

```sh
npm run test:measurement
npm run per36
npm run per36 -- --team GSW --n 1000
npm run per36 -- --team GSW --pace 100 --seed 20260908 --n 1000
npm run per36 -- --opponent-pr 90
npm run test:rebound-blocks
node scripts/compare_opponents.js
npm run reference:refresh
```

報表寫入 `reports/per36.md` 與 `reports/per36.json`；單隊執行使用 `per36-gsw` 等獨立檔名，避免覆蓋完整報表。資料來源為 `data/reference-seasons.json`，附 NBA 官方端點、抓取日期與原始計數。一般報表離線執行；只有更新來源時需要網路。

PR90 報表使用 `per36-pr90` 檔名。比較報表需要先完成兩組同樣 n／seed／pace 的報表，舊版保存在 `reports/baselines/per36-v1.json`。原存檔每隊 1,000 場；用其他樣本數時比較工具會拒絕直接混比。

## 時間與比較對象

每方目標回合數為 `pace × 36 / 48`；取最近整數後，揭露實際等效分鐘，計數再按比例換算成 per-36。命中率與 usage 不按時間乘倍數。真實 per-36 為 `賽季總計 × 36 / 賽季總分鐘`，不是直接抄場均數字。

五名球員同時上場，舊版預設對全70合成基準隊。單項屬性PR90轉為全屬性94；其進攻和防守都更強，不是只有防守提高，也不是聯盟平均。使用現有五支測試隊的同隊同季資料，不是 60 張巔峰卡混搭陣容。官方球隊攻防數據含完整輪換與各種對手，這裡僅作背景，不拿不同條件的差距直接作球隊強度驗收。

`simulateGame` 的 `fatigue` 預設仍是 `true`，保留一般比賽行為。per36 報表固定使用 `false`，完全略過疲勞對投射與切入的衰減。疲勞與輪換成熟前，這是主要診斷模式。

## 計數與缺口

引擎回傳 `playersA`、`playersB`，直接計數得分、分區投籃、罰球、失誤、進攻／防守籃板與已建模的傳球攔截；Monte Carlo 同時聚合雙方統計。所有比率以累計分子／分母計算，零出手的新命中率欄為 `null`。

- 籃板：新模型使用 30% 均等落點運氣，加上 70%「接近落點的機會 × 能力」。能力的指數溫度由舊版 9 放緩至 45；落點區分內線／外線，三分失投更容易形成外線機會。進攻端另計搶板參與度與投籃者預期位置；防守端不使用進攻搶板參與度。團隊進攻籃板機率沿用原公式，這輪改分配、不宣稱所有球隊 OREB 總量已校準。
- 位置：`courtPosition` 可指定本場 PG／SG／SF／PF／C，未指定時用 `pos`；例如讓 Green 打 C 會增加內線機會與職責。不推導完整戰術、不模擬座標，也不自動根據名字安排位置。各位置權重與落點比例都是公開的原型假設，不是追蹤資料估計值。
- 防守籃板歸屬使用獨立 seed 亂數；進攻籃板歸屬會改變補籃者，因此新版比分與球權可隨之改變。`reboundModel: 'legacy'` 保留舊版重現；預設是 `'opportunity'`。
- 抄截：目前只計現有傳球攔截事件，歸給當時對位防守者；走步、進攻犯規或其他控球失誤不自動變成抄截。
- 火鍋 beta：每區有基礎每次出手封阻率（近射 .095、中投 .022、三分 .006），再依護框／身材與對位／內線職責調整。這些是待校準初值。外線以直接對位為主，近射納入協防。防守命中曲線本來已含封阻影響，所以將既有未進球按 `P(封阻) / P(未進)` 條件抽樣，絕不另扣命中率；封阻之後仍有籃板。`blk` 與被封阻的 `blka` 雙方守恆，事件 log 附 `blocker`。邊界限制最多 65% 未進球被分類為封阻。尚未模擬封阻出界與二次進攻時鐘。
- `blocks: false` 可關閉火鍋分類；預設為 `true`。獨立封阻亂數不改比分、出手、罰球或籃板。這是觀測事件的細分，不能宣稱新增了一套獨立阻止得分的物理機制。
- 罰球未進後的籃板、團隊籃板與助攻尚未完整建模／記帳。
- 超過六次進攻機會的強制結束記 `truncations`，不偽造失誤或防守籃板。
- 舊 log 仍最多 400 筆；個人與團隊統計不受它截斷。

## usage 與包夾

`usagePct = 100 × (FGA + 0.44 × FTA + TOV) / 全隊同口徑合計`，用於五人同時上場的估计。`eventSharePct` 另計投籃／罰球行程／失誤的事件份額；進攻籃板後的新投籃也是新事件，因此不把它叫做已結束 possession 份額。

官方整季 USG% 使用不同上場情境，不能視為此五人陣容的精確答案。報表同時提供原值與五人正規化代理值，但不以代理誤差證明公式正確。

診斷欄追蹤初始持球、接球份額、出手機會 EV、模型包夾率及傳球被攔截率。EV 與包夾率在走到投籃／持球失誤判定的機會上取平均；傳球鏈提早攔截的回合不包含在這兩項平均。包夾率是公式機率，不是已抽樣發生的包夾事件頻率。

後續公式方向：保留高 EV 球員得到更多球權的原則；防守依未包夾威脅、隊友放空代價等決定包夾，包夾後再評估出手品質與處理失敗。處理球差應增加失誤，球權自然轉移。不要根據同一瞬間的「已被包夾後低 EV」立刻取消包夾，否則會產生開關震盪；應求穩定混合防守或有阻尼的調整，再檢查 usage 是否貼近真實。優先用已有屬性，不先增加手填數字。

## OVR 的最新驗收定義

使用者指定：同一規則、同一對手、四名平均隊友的情境中，OVR 高者應有較高勝率。後續 OVR 應由這個固定基準勝率作單調映射；淨得分貢獻及多情境結果作解釋與穩健性診斷，不能再拿淨分差排序當成勝率排序的保證。

固定 seed／曝光、處理先後手與位置差異，報告勝率不確定性；非常接近的球員可同 OVR。這是對定義好的基準測試單調，不保證每次隨機比賽都贏，也不保證任何陣容對戰都無克制。卡費仍只用於近似單調檢查，不能倒灌進 OVR。

## 驗證

`test/measurement.js` 包括舊版模式的 20 組結果指紋、雙方記帳守恆、命中與得分恆等式、log 截斷、罰球與攔截分支、疲勞開關、雙方 Monte Carlo 聚合與抽樣誤差、時間換算及資料賽季匹配。PTS／REB／TOV／BLK 的均值區間只估計抽樣誤差，不包含真實資料誤差或模型偏差。

`test/rebound_blocks.js` 檢查運氣保底、能力及位置效果、長籃板對後衛的機會、封阻區域與護框單調性、封阻與未進／籃板守恆，以及火鍋開關不重複扣命中率。罰球曲線的原始錨點保留，沒有因校準得分而改動。

2026-09-08 舊輪結果（不是本輪）：25 人全70對手籃板 MAE 6.39→0.93，進攻籃板 1.53→0.58；但得分 MAE 2.56→2.81、usage 代理 MAE 1.69→1.99，不能把籃板改善說成整體校準完成。PR90 二分／三分誤差縮小，卻使得分、籃板與 usage 整體誤差更大。下一步仍需改善球權／包夾與同條件對手基準，不能選一支讓特定球員剛好對得上的對手當答案。
