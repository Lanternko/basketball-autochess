# 共用記憶（memory/）

所有 agent（Claude Code、Codex、派工子 session、雲端 thread）**只透過這個資料夾溝通**。不靠對話交接：要交給別的 agent 的事，一律寫進 `handoff.md` 或對應欄位檔。
記憶不是逐日敘述，而是固定欄位的條目。架構照 jev-hearthstone 的 `memory/`，源自 AutoTavern 論文（arXiv 2610.33845 §4、附錄 A）的 typed research memory。

2026-10-28 建立時，從 README「踩過的坑／已知限制」、`reports/status/status.md`、git log（`8d18901`…`560ddcc`）、`reports/ovr-inseason-2026-27/v5/pathA/` 與 Claude 的 auto-memory 搬入初始條目。逐份報告仍在 `reports/`，條目只寫結論並指向報告。

## 開工必讀順序

1. `handoff.md`（現在在做什麼、下一步）
2. `lessons.md`（不要再犯的錯）
3. `rulings.md`（使用者的裁定，卡片與驗收不得違反）
4. 其餘按需查：`grep -n "關鍵字" memory/findings.md memory/experiments.md`

## 寫入規則

- **只追加新 ID**：新條目接在檔尾，ID 取該檔目前最大號 +1。不重編號、不刪條目。
- **一筆一件事**：一個發現、一次實驗、一條裁決、一個教訓各一筆；彼此用「相關」欄位互指（例如 `F-012、E-034`）。
- **狀態改變時改原條目**：只改「狀態」欄，括號註明日期與原因，例如 `被推翻（2026-11-02，E-040 重跑後 ρ 0.41）`；同時寫一筆新條目說明新證據，兩筆互指。
- **數字照量到的寫**：證據欄寫指令、檔案路徑與數字；沒量過的寫「待驗」，不要寫成已證實。
- **樣本內不算證據**：卡片若用 RAPM 做 align／封頂／混合目標，它對 RAPM 的 ρ 只能寫「樣本內」，不能當驗證（R-007）。
- **抓到錯誤就寫 lesson**：每個被抓到的錯誤（使用者指出的、測試抓到的、自己發現的）寫成一筆 lesson；能自動檢查的就加測試，把測試檔或 npm 指令寫進「對應測試或關卡」。
- **收工**：新發現、實驗、裁決、教訓各寫進對應檔，然後**覆寫** `handoff.md`。模型或卡片輸出有變時，另照 L-021 重產審查表。
- 欄位定義與範例寫在各檔檔頭。
- 「來源」欄：commit、報告路徑或對話日期；沒有就省略。

## 五道門

一個結果沒過它該過的門，就不寫成「已證實」。

| 門 | 內容 | 怎麼檢查 |
|---|---|---|
| G1 構建 | 改動後測試全綠 | `npm test`；改到特定批次時加跑對應的 `npm run test:<批次>`（例如 `test:ability-eighth-c`） |
| G2 契約 | 每張卡、每個模擬板都記得它用的模擬版本、RAPM 季窗與資料來源（含 stint 來源與 sha256） | 報告或 json 寫明版本與來源雜湊；來源不一致就不能拿來比（F-021、L-018） |
| G3 比較 | 只在同一模擬版本、同一人群（例如 pooledPoss ≥ 5000）、同一組 seed 下比較；隨機性要用球隊＋seed 重抽區間 | 報告寫明人群門檻、seed 數與區間算法 |
| G4 樣本外 | 參數在已看過的資料上選；交付前在沒參與挑選的資料上再測一次（RAPM 分半 A→B／B→A、沒看過的季、預註冊凍結後才看的起點） | 預註冊檔先凍結（附 sha256）再看答案；讀 RAPM 的卡不拿 ρRAPM 當證據 |
| G5 現實 | 使用者抽查：熟悉球員的名次、前十長人組成、2K27 或 RAPM 其一對得上；賽中 OVR 對真實賽季 | 審查表（`reports/status/`）＋球員抽查表（R-003、R-004） |

## 角色

照 AutoTavern 的分工，派工時 task 開頭寫「用 role-xxx skill」（`.claude/skills/role-*/SKILL.md`）；不是 Claude 的 agent 直接讀那份 SKILL.md。角色之間只透過這個資料夾交接。

| 角色 | 負責 |
|---|---|
| `role-lead` | 讀 handoff 挑下一個問題、寫 spec、審結果、收工寫 memory。不自己實作。 |
| `role-model` | 模擬引擎與數值模型（`src/`、possession、防守、球權）。 |
| `role-card` | 卡片 OVR、屬性建構、賽中 OVR。 |
| `role-audit` | 樣本外驗證、回測、審查表；必須和產生該結果的 session 不同。 |
