# 經驗教訓（lessons）

做事方法、建模、流程與量測方法的教訓。每個被抓到的錯誤寫一筆；能自動檢查的就加測試。讀寫規則見 [README.md](README.md)。

欄位（固定）：
- **ID**：`L-001` 起，只追加。
- **日期**
- **發生什麼**
- **規則**：以後一律怎麼做。
- **對應測試或關卡**：測試檔、npm 指令、評估門檻或流程關卡；沒有寫「無」。
- **相關**：其他 ID。
- **來源**（選填）

範例：

```
### L-999
- 日期：2026-10-28
- 發生什麼：驗收寫了「OVR 40–99」，四張卡被判 FAIL，其實是條件寫錯。
- 規則：卡片驗收用 rank ρ 與中位數，不用固定範圍。
- 對應測試或關卡：預註冊審查
- 相關：R-005
```
