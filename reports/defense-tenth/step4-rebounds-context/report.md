# 同一球員換角色與隊友：OREB 機會診斷

**結論：兩個角色／隊友替代量皆未增加可確認的 OREB 預測價值，合併版本也未通過。暫不據此修改角色倍率、卡位係數或引擎。** 兩個檢查季等權合併，OREB／36 MAE：上半季原率沿用 0.35151，個人歷史 0.35512，加角色 0.35468，加隊友競爭 0.35488，兩者 0.35391。三候選對沿用原率與個人歷史的主要聯合區間均跨 0。

本批四季均**已看過答案**；以 2022–23、2023–24 估計，以 2024–25、2025–26 檢查。同季上半資料是截止前特徵，後半真實陣容與分鐘分配是**答案側的條件式診斷**，不是完全事前預測。沒有使用球隊淨勝分、效率、勝場、排名、正負值或區段攻守殘差來建模；區段僅提供場上五人與時間。沒有跑新模擬或改卡。

## 規則、理由與資料門檻

前一批的季彙總只能測「球員歷史是否穩定」。此次改成同人前後半變化，檢查隊友／角色變化能否提供原率沒有的資訊。若這條機會路徑有用，預期會降低機會預測誤差，再透過固定的上半季取得率降低 OREB 誤差；不預先指定改善量或強迫係數方向。

登記版本 `oreb-context-offline-1`，UTC `2026-10-14T08:55:35.946236+00:00`；SHA-256 `70f9cd6df97ad1e041eaf17a31bb153082d477ec033e8620efbd069074662968`。

- 聯盟共同日曆截止日：例行賽中位場次的日期；該日全部比賽歸上半，其次日開始下半。NBA Cup 決賽不在官方 `002` 例行賽樣本內。
- 新取得八份官方 `leaguedashptstats / Rebounding / Totals`，四季各前後半；回傳日期、GP 與原全季計數均核對。每名球員前＋後半的 OREB、機會數都精確等於已快取全季值。
- 只用既有嚴格場次的場上五人，沒有另調換人或分鐘。入樣兩半各至少 200 box 分鐘、100 追蹤分鐘，上半至少 10 次機會，兩半嚴格區段覆蓋各達本人 box 分鐘 70%。所有排除逐人保留。
- 組織角色：上半季 AST／36 在該五人中最高者的在場時間占比；同值均分。這只是組織任務代理，**不是實際持球時間或控衛位置**。
- 隊友競爭：另外四人的上半季機會／36 加總，依共同在場時間加權。固定使用上半季能力；缺資料／下半新出現者用上半季聯盟中位數，不偷取下半能力。
- 各模型基礎同為本人上半機會／36、log(上半 box 分鐘＋1)、AST／36；分別加入角色占比變化、隊友競爭變化、或兩者。只估機會變化，不改取得率。預測 OREB／36＝預測機會／36×上半季原始取得率。
- 五折以球員 ID 雜湊分組，ridge 只用前兩季選；ID 與球隊僅作配對／分組，不當特徵。沒有校正後半聯盟常數或看結果改倍率。
- 20,000 次球隊＋球員聯合重抽；同人同球隊跨季配對，季內分鐘加權、兩個檢查季等權。沒有模擬 seed 或重新訓練模型的不確定性。
- 主要六筆為三候選各對原率沿用／個人歷史的合併 OREB MAE；95% 與 Bonferroni 99.1667% 同報。其餘為探索，不用於採用。

只有個人歷史的模型已把原機會沿用 MAE 從 0.52608 降到 0.50314。再加入角色／隊友，沒有進一步改善；兩者合併反而是 +0.01027，未校正 95% [＋0.00045, ＋0.01971]，99.1667% 跨零。這是離線機會預測的副作用，不是引擎籃板、快攻或戰績副作用。兩者模型的 ridge 由訓練折選到 1000，其他為100，不能把差異完全歸因於單一角色路徑。

2025–26 的候選機會數都贏原機會沿用，但個人歷史已做到，候選與個人歷史仍分不出；不能誤認為角色造成增益。完整各季與換隊區間在 `results.json`。

## 已驗證、推測、失敗與停止

- **已驗證：**日期篩選通過，分段計數守恆；可重建的陣容時間與個人前半數據能形成兩個獨立代理；兩代理沒有確認超過原率沿用與個人歷史。
- **推測：**AST 排序沒有捕捉出手當下站位／退防任務；季半平均的隊友機會數也沒有捕捉共享落點與卡位配對。取得率變化可能限制固定取得率路徑，但本批依可歸因規則不另修它。
- **失敗：**未辨識可泛化的角色機會係數、未確認換隊收益、未驗證卡位因果貢獻。兩代理一起加入的機會誤差有未校正退步。
- **限制：**已知後段陣容的答案側診斷，不是季前預測；機會數並非按陣容區段觀測，所以仍有聚合誤差。人員選擇、投失頻率、投籃分區、戰術與傷勢未因果控制；沒有偽造座標或把結果誰拿到板當成起始機會。
- **決定：**本批到此停止，維持引擎。不能宣稱 DREB、球隊 OREB 或 net／勝場 MAE 改善。下一個資料優先序應為核對官方機會口徑及可取得的逐次空間／卡位標籤，尚未下載或啟動下一批。

## 格式修復與重跑

初版將 API 回傳 `MM/DD/YYYY` 與登記的 `YYYY-MM-DD` 字串直接比較，誤判八筆日期。原程式、原稽核與原停止決定已保留；`analysis-code-repair-1.json` 在修正結果產出前登記，只做日期同義正規化與修復鏈鎖。沒有變動 protocol、截止日、樣本門檻、模型、資料或判準。

保留登記，不重跑 `register.py`；`fetch.mjs` 重用快取：

```powershell
node reports/defense-tenth/step4-rebounds-context/fetch.mjs
python reports/defense-tenth/step4-rebounds-context/analyze.py
python reports/defense-tenth/step4-rebounds-context/report.py
python reports/defense-tenth/step4-rebounds-context/audit.py
```

`data-audit.json` 完整資料門檻；`cohort-exclusions.json` 所有排除；`samples.json` 逐人前半與後半條件；`prefix-profiles.json` 來源期個人數據；`lineup-contexts.json` 角色代理；`fits.json` 訓練選擇與係數；`predictions.json` 逐人預測；`results.json` 所有配對區間；`completion-audit.json` 保護與重算稽核。
