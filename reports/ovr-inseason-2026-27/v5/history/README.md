# v5 延伸回測資料：2010-11～2023-24 的 stint、RAPM 與分鐘數

**用途**：`preregistration-v5.md` §4、§5 想把起點鏈延伸到 2014-15～2020-21（Y0–Y6），但本機沒有這幾季資料，stats.nba.com 與 cdn.nba.com 也抓不到。這個資料夾是改用 NBA 官方資料的 GitHub 鏡像重建的結果。本資料夾不修改預註冊任何章節，§R 原文未動。

## 資料來源

兩個來源都是 NBA 官方端點的原始輸出存檔，從 `raw.githubusercontent.com` 下載（雲端環境連不到 nba.com，但連得到這裡）。

| 內容 | 來源 | 原始端點 |
|---|---|---|
| 逐球紀錄 | [shufinskiy/nba_data](https://github.com/shufinskiy/nba_data) `datasets/nbastats_<起始年>.tar.xz` | stats.nba.com `playbyplayv2` |
| 每場球員 box score | [NocturneBear/NBA-Data-2010-2024](https://github.com/NocturneBear/NBA-Data-2010-2024) `regular_season_box_scores_2010_2024_part_{1,2,3}.csv` | stats.nba.com `boxscoretraditionalv3` |

- 檔名的年份是球季起始年：`nbastats_2016` 是 2016-17。
- 每季原始檔的 sha256 記在 `stints/preparation-<季>.json` 的 `sources`。
- 同一個鏡像還有 `shotdetail_<年>`（投籃位置）和 `nbastatsv3_<年>`，需要時可以用同樣方式下載。這次沒有用到。

## 檔案

| 檔案 | 內容 |
|---|---|
| `stints/stints-<季>.jsonl.gz` | 2010-11～2020-21 每段 stint，格式與 `scripts/prepare_defense_b1.js` 相同（`id`、`period`、`seconds`、`teams[i].teamId/players/opponent.points/defensivePossessions`），球員 ID 是 NBA personId |
| `stints/preparation-<季>.json` | 每季可用場數、排除的比賽與原因、來源雜湊 |
| `rapm-<首季>_<末季>.csv` | 四季合併 RAPM：`playerId,name,net,O,D,poss`（每 100 回合） |
| `summary.json` | 每個目標季對應的預測端／答案端 RAPM 檔、λ、交叉驗證誤差、每季資料品質 |
| `box-totals-<季>.csv` | 2010-11～2023-24 球員整季官方 box 合計。`teamId=ALL` 是跨隊加總（被交易球員已加總），其他列是分隊 |
| `box-games-<季>.csv.gz` | 每場球員 box score（秒數、先發、各項數據），給季中第 3、5、10、20 場的檢查點用 |
| `validation-onoff.json` | 與 repo 現有 on/off 的對照（見下） |

重建指令：

```
python3 -I scripts/build_historical_stints.py --pbp nbastats_2016.csv --box <box csv 資料夾> --season 2016-17 --out <輸出>/2016-17
python3 -I scripts/historical_rapm_windows.py --stints <輸出> --box <box csv 資料夾> --out reports/ovr-inseason-2026-27/v5/history
```

RAPM 直接呼叫 `reports/impact-rapm/rapm.py` 的 `observations`、`fit_rapm`：模型、λ 候選值、依比賽分組的 5 折交叉驗證都和正式卡相同。九個視窗選出的 λ 都是 3000，和 repo 的 2022-23～2025-26 一樣。

## 重建方法

- **先發**：第 1 節用 box score 的先發；之後各節看誰先有動作、或先被換下，就是該節先發。湊不滿五人時（每季 6～23 個節次），補上「重建分鐘最不足 box 分鐘」的隊友。
- **排除規則**：每位球員重建出的上場秒數必須和 box score 相差 2.1 秒內，雙方總分也要對上，否則整場不進 stint。這和 `prepare_defense_b1.js` 一樣是整場排除，只是容許誤差從 1.1 秒放寬到 2.1 秒，因為這份 box score 只到整秒，且舊球季的官方 box 常有 ±2 秒的進位修正。
- **回合**：投進（and-one 時改在罰球結束）、一輪罰球的最後一罰、活球防守籃板、失誤、節末，各算一個回合結束，記在當下的 stint。`prepare_defense_b1.js` 是依比賽時鐘按比例分攤到 stint，所以單段 stint 的回合數會有小差異，整季總數一致（得分效率比值 1.002）。
- **得分**：用逐球紀錄的比分變化，不自己判斷幾分球。

## 驗證：和 repo 現有 on/off 對照

用本方法重建 2022-23、2023-24，與 `reports/impact-rapm/onoff.csv`（cdn liveData 管線）比較，只看 repo 檔中在場超過 2,000 回合的球員-球隊：

| 季 | 人數 | 在場進攻效率 r | 在場防守效率 r | 在場淨效率 r | on-off 差 r | 淨效率平均差 |
|---|---|---|---|---|---|---|
| 2022-23 | 374 | 0.965 | 0.945 | 0.966 | 0.945 | 1.14 |
| 2023-24 | 358 | 0.976 | 0.963 | 0.978 | 0.943 | 1.21 |

- 兩條管線排除的比賽不同（本方法保留較多場），所以不會完全相等；在場回合數相關 0.99，本方法多 7～9%，主要是多保留的比賽。
- 結論：兩條管線量到的是同一件事，可以合併使用，但數值不是逐位相同。

## 已知缺口

- **身高體重**：這兩個來源都沒有。2014-15～2020-21 球員中，2021-22 以後還有出賽、本機已有身高體重的比例（以分鐘加權）：2014-15 44%、2015-16 56%、2016-17 64%、2017-18 70%、2018-19 82%、2019-20 91%、2020-21 97%。如果 v4 建卡流程需要 `heightInches`、`physique`，舊季要另找來源或用位置預設值。
- **投籃位置**：如果 `long/mid/short` 需要投籃距離分區，要另外下載同一鏡像的 `shotdetail_<年>`，這次還沒做。
- **季後賽**：沒有處理，只有例行賽。
