# v55 第一步：NBA 2K27 評分 × 卡片 OVR × v54 模擬板 × RAPM 三方對照

產生時間：腳本 `merge_and_analyze.py`；抓取腳本 `fetch_2k27.py`。卡片板 582 人，成功取得 2K27 評分 575 人，**涵蓋率 98.8%**。

## 0. 重要前提：2K 不是真值

- NBA 2K27 總評是遊戲設計者的主觀評分，有明顯的「明星名氣」與遊戲平衡考量，**不是球員價值的真值**。
  這裡只把它當作第三個獨立參考點，用來找「我們的卡片板和外部共識不一致」的地方。
- 2K27 的名單對應的是 2026-27 球季開季版本，我們的卡片板是 2025-26 資料；季別落差會讓新秀、剛轉隊、傷癒復出的球員出現系統性偏移，這類球員的差距不要直接當成我們的錯。
- 2K 的屬性分佈本身也被遊戲機制壓縮（例如 Pass Vision 給長人普遍很低），所以屬性對照看的是 **排序一致性（ρ）與分組方向性偏差**，不是絕對值差。

**2K 抓取做法**（最終採用：內建瀏覽器同源 fetch）

`fetch_2k27.py` 用 Python `requests` 直接抓會被 2kratings 回 403，所以改在內建瀏覽器開 2kratings.com，在頁內以同源 `fetch` 逐一讀球員頁（每頁間隔 2–4 秒、單頁 20 秒逾時、連續被擋 4 次即停；未解任何 CAPTCHA）。球員頁 JSON-LD 給 2K27 總評與 31 項屬性，`chartjs-dashboard-line-year` 折線圖給 2K19–2K27 逐年總評。結果以 `slug|pos|數字串` 分段匯出到 `cache/browser_chunk_*.txt`（每段核對長度＋雜湊），再由 `build_from_browser.py` 轉成 `2k27_ratings.csv`、`2k_yearly_ovr.csv`、`unmatched.csv`。slug 候選清單（名字正規化＋別名）沿用 `fetch_2k27.py` 的對應規則，存在 `slug_candidates.json`。

原本 `fetch_2k27.py` 的流程（保留供參考）：

1. 先抓 30 支 NBA 隊伍頁與 G-League 附屬隊頁，從頁內的 JSON-LD（`schema.org/Person` 的 `additionalProperty`）建立「球員名 → 網址 slug ＋ 總評」索引。
2. 名字對應流程：先用重音正規化（`Dončić`→`doncic`、`Porziņģis`→`porzingis`、`Dëmin`→`demin`）＋去掉 `.`、`'` 後比對；比不到再去掉 `Jr./Sr./II/III/IV` 後綴比對；再不行查人工別名表；最後退回「由名字直接推導 slug」試打球員頁。
3. 逐一抓球員頁，從 JSON-LD 取 31 項屬性，位置取自簡介段落的 `/lists/<position>` 連結。
4. 禮貌抓取：HTML 全部存本地 cache（`cache/`，未進版控）、每次請求間 sleep 1 秒、帶一般瀏覽器 User-Agent、遇 403/429/503 以遞增等待重試 3 次，連續 8 個頁面被擋就直接中止並回報。**沒有做任何繞過 bot 偵測或解 CAPTCHA 的事。**

**抓取正確性檢查點**


- Karlo Matković：2K27 總評抓到 **74**（任務給的期望值 74）。卡片 OVR 95.4（第 7 名）、2K 第 294 名、RAPM 多季第 212 名、單季第 230 名。


**名次定義**：`cardRank` 是卡片板原始名次（582 人內）；`rank2k` 是在「成功對應到 2K 的子集」內依 2K 總評由高到低的平均名次；RAPM 名次是在各自的樣本量門檻子集內排。`rankGap = rank2k − cardRank`，**正值＝卡片給的名次比 2K 高，也就是卡片相對高估**。


### 1.1 原型判定規則

```
原型判定規則（依序判定，先中者為準；只用卡片屬性與 box score，不看 2K）：

1. 吃餅長人（roll-man / 餵球終結型長人）
   （身高 ≥ 81 吋 或 位置屬 PF/C）
   且 short ≥ 75（近框終結在全板 p75 以上）
   且 pass ≤ 60 且 creation ≤ 60（不是傳球或持球樞紐）
   且 AST/36 ≤ 2.5。
   註：這裡刻意不卡三分出手佔比。現代長人會投幾顆三分（例如 Matković 的 threeRate 0.38），
   但出手量很小，卡了反而會把最典型的吃餅長人漏掉。

2. 持球創造（on-ball creator）
   creation ≥ 85（全板約 p92）或（pass ≥ 75 且 AST/36 ≥ 4.5）。

3. 3D（投射＋防守側翼）
   long ≥ 68 且 三分出手佔比 ≥ 0.38 且 AST/36 < 4 且 creation < 85
   且 max(onBall, help) ≥ 50。

4. 其他
```

## 6. 結論與 v55 修正方向

### 6.1 三方一致性（全體 n≈575；RAPM 子集 n≈410–500）

- **2K27 和 RAPM 的一致度不比卡片高**：2K27 vs 多季 RAPM ρ=.549、單季 .462；卡片 OVR vs 多季 RAPM .500、單季 .501；v54 模擬板 vs 單季 RAPM .515。三者都在 .45–.55 一帶，2K 不是比我們更準的參考點，只是另一個有雜訊的觀點。
- **卡片 OVR vs 2K27 只有 ρ=.449，而且幾乎全部來自 1300+ 分鐘桶（.664）**；<800 分鐘桶 ρ≈0。小樣本球員卡片名次的分歧，主要是我們的 per-possession 估計在低分鐘時還沒收縮夠（2K 對這群人幾乎一律給 68–71）。這和 v54/v55 替補收縮的方向一致，不是新問題。
- **v54 模擬板 vs 2K27 ρ=.457**，比卡片略高，但在 1300+ 桶（.477）明顯低於卡片（.664）：模擬板對主力球員的排序跟外部共識差得比較遠。

### 6.2 逐年 2K（2K19–2K27）

- 2K26（2025-26 季前評分）跟 RAPM 單季只有 ρ=.339，2K27（看完 2025-26 季後評的）升到 .462 —— 2K 自己也會依據一季表現大幅修正，這個「季後版」才是跟我們卡片同期的比較對象。
- **2K27−2K26 的升降幅度和單季 RAPM 幾乎無關（ρ=.172）**，和卡片 OVR 也無關（ρ=.112）。2K 的年度升降多半是新秀成長曲線、名氣與合約，不是場上影響力；不建議拿 2K 的升降來校準我們的季內變化。
- 2K 三年平均（25–27）vs 多季 RAPM ρ=.527，**不比單一 2K27（.549）好**，多年平均沒有額外資訊。
- 572 人同時有 2K26 與 2K27，平均升降 +0.3，整體分佈很穩。
