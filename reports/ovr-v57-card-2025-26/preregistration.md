### 1.2 為什麼側翼沒受益？不是離散度問題，是「限定 PF/C」這一條

v56 的診斷把長人防守低估歸因於 `help`/`onBall` 屬性離散度被壓縮。本輪進一步檢查**各位置的 RAPM
防守離散度**，發現這個解釋**不能**延伸到位置差異：

| pos | 池內人數 | SD(pooledD) | SD(centeredD) | max(centeredD) | P90(centeredD) | SD(help) | SD(onBall) |
|---|---|---|---|---|---|---|---|
| PG | 78 | 1.602 | 1.201 | 3.433 | 1.502 | 7.09 | 5.88 |
| SG | 97 | 1.531 | 1.148 | 3.860 | 1.289 | 5.86 | 5.46 |
| SF | 81 | 1.594 | 1.196 | 3.040 | 1.358 | 6.14 | 5.60 |
| PF | 68 | 1.541 | 1.156 | 2.356 | 1.494 | 8.51 | 5.41 |
| C | 90 | 1.626 | 1.219 | 4.073 | 1.307 | 9.96 | 6.52 |

`centeredD` 的 SD 在五個位置幾乎一樣（1.148～1.219，差距 < 6%），`max(centeredD)` 的最大值反而出現
在 SG（Caruso 3.860）與 C（Wembanyama 4.073）。**所以同一個 γ 套在所有位置上，各位置拿到的加分
分佈本來就是可比的；側翼拿不到加分純粹因為 `BONUS_POS = {PF, C}` 這個硬限制。** 真正有位置差異的
只有加分的「基準點」`posMeanD`（C +0.574、PF +0.426、SG +0.122、SF −0.144、PG −0.220），而這已經
在公式裡用位置均值扣掉了。

**由此直接否決一個看似合理的候選：「把 `centeredD` 再除以各位置的 SD 做跨位置標準化」**——因為
SD 幾乎相同（1.148～1.219），這個候選實質上是 γ 乘以 0.82～0.87 的常數，等價於微調 γ，不是獨立
機制，不值得占一個候選名額。

**另一個被否決的候選：「直接把 `help`/`onBall` 的聯盟離散度拉開（線性 re-spread）」**——回歸的設計
矩陣對每個屬性做 z-score 標準化（`design()` 裡 `z = (raw - mean)/sd`），對屬性做線性縮放後 z 不變、
預測值完全不變，是數學上的 no-op（除非縮放撞到 40/99 的夾擠邊界而產生非線性，但那會變成不可解釋的
裁切效應）。另外本任務也不允許修改 `scripts/build_season_league.js`。

## 二、候選修正方向（全部是固定先驗，不自由估計係數）

全部疊加在 **E2-λ0.4 的卡片 league**（`reports/ovr-v55-card-E-2025-26/season-league-E2-lam0.4.json`）
之上，**不碰吃餅折扣**、不碰回歸係數本身、不碰 `data/`、不碰 `scripts/build_season_league.js`。
實作方式：新增 `reports/ovr-v57-card-2025-26/calibrate-wing.py`，從
`reports/ovr-v56-card-defense-2025-26/calibrate-defense.py` 複製核心邏輯（原檔唯讀），加
`--direction=G1|G2|G3|G4` 與 `--gamma` / `--delta` 參數。

### 共用定義（與 v56 完全一致，數字由同一套程式重算）

```
BLEND_PER36 = 0.75 ; BLEND_POSS = 1000 ; BONUS_MIN_POSS = 5000 ; alpha = 0.5
pos            = calibration-target-B12.csv 的 position 欄（即 ranking.csv 的 pos，不是身高分桶）
posMeanD(pos)  = MIN 加權平均 0.75*pooledD，池 = 同 pos 且 pooledPoss >= 1000
                 （實測值：C +0.5742, PF +0.4258, SG +0.1222, SF -0.1444, PG -0.2204）
centeredD(i)   = 0.75*pooledD(i) - posMeanD(pos(i))
r(i)           = 0.75*pooledNet(i) - MIN 加權位置均值（同池），即 calibrate.py::attach_rapm 的 r
pred0(i)       = 回歸預測值（未加任何修正項）。G1~G4 都不改回歸目標、不改設計矩陣、不改 ridge，
                 所以 pred0 與 E2-λ0.4 的 predictedPer36 完全相同（修正項全部是 pred 的後處理，
                 發生在 percentile 映射到 OVR 之前）。
PR(i)          = pred0(i) 在縮放參考池（MIN >= 500, n=379）內的百分位（0~100）
```

### G1：防守加分擴及全位置（移除 `pos ∈ {PF, C}` 限制）

```
bonus(i) = gamma * max(0, centeredD(i))     若 pooledPoss(i) >= 5000（任何位置）
         = 0                                 其餘
pred(i)  = pred0(i) + bonus(i)
```

- **作用對象**：`pooledPoss ≥ 5000` 且 `centeredD > 0` 的所有球員（F2 下只有 PF/C 拿到）。
- **候選值（跑結果前鎖定）**：`γ ∈ {0.5, 0.75}`。`γ=0.5` 與 F2 代表版同值（最小變動）；`γ=0.75`
  是因為 1.1 的反推下界顯示 Herbert Jones 需要 ≥0.60，而單調估計是下界，需要安全邊際。
- **預期副作用**：長人加分完全不變（與 F2 一致）→ 前十長人問題**不會改善**，只會因為側翼上移而
  略被擠下。側翼／後衛大批上移，`pooledPoss < 5000` 的低分鐘球員相對被壓低。
- **對 v56 已過 9 項門檻的侵蝕風險**：七人全是 PF/C，加分值與 F2 完全相同 → 七人門檻**理論上不受
  直接影響**，但他們的**名次**會因為大量側翼上移而變差（Gobert 第 13、Queta 第 28 離門檻 60.5／110.5
  還有很大空間，風險低；Karlo 第 19 需要 ≥17，側翼上移反而幫他掉名，風險低）。ρ(2K27) 是主要風險：
  被救的側翼裡 Thybulle（2K27 294.5）、Holland（255.5）、Jones（142）的 2K27 名次都很差，把他們
  大幅上移會拉低 ρ(2K27)。

### G2：G1 ＋「只修低估」taper（避免獎勵已在頂端的球員）

```
w(i)     = clip( (96 - PR(i)) / (96 - 90), 0, 1 )        # PR<=90 -> 1 ; PR>=96 -> 0 ; 中間線性
bonus(i) = gamma * max(0, centeredD(i)) * w(i)           若 pooledPoss(i) >= 5000
pred(i)  = pred0(i) + bonus(i)
```

- **固定先驗**：`PR_lo = 90`、`PR_hi = 96`（**跑結果前寫死，不調**）。選這兩個數字的理由在 1.5：
  要救的人 PR ≤ 87.1（Gobert 79.1、Queta 86.2、全部側翼／後衛）、要壓的人 PR ≥ 94.7
  （Karlo 94.71、Gordon 95.50、Embiid 97.35、Mobley 98.68），90/96 是這兩群之間唯一不需要看
  結果就能定出的分界，且 90 與 96 都落在兩群之間的空隙。
- **候選值**：`γ ∈ {0.75, 1.0}`。因為 taper 會削掉一部分加分，γ 需要比 G1 略大才能維持側翼修正力度；
  Gobert（PR 79.1）`w=1`，加分與 F2 的 γ 同義。
- **預期副作用**：Embiid 加分 0.907→0（`w=0`）、Mobley 0.704→0、Gordon 0.933→約 0.078（`w≈0.083`）、
  Wembanyama／Chet／Jokić／Giannis 加分全部歸零（他們 PR ≥ 98.4）。前十長人數預期回到 E2 基準的
  5 人附近，**但 Mobley 仍在前十**（他在 E2 基準不靠加分就第 6），所以 G2 無法單獨達成
  「Mobley 不在前十」。
- **對 9 項門檻的侵蝕風險**：Gobert（w=1）、Queta（PR 86.24 → w=1）加分不受影響，門檻安全；
  Karlo（PR 94.71 → w≈0.215）加分從 0.315 降到約 0.068，**對「Karlo 掉 ≥10」門檻比 F2 更安全**；
  Stewart／Jalen Smith 加分本來就 ≈0。副作用：Wembanyama 失去 2.036 加分會從第 1 退回第 2 附近
  （E2 基準的位置），這本身不違反任何門檻，但要如實回報。ρ(RAPM pooledD) 可能比 F2 的 0.3624 下降
  （因為削掉了頂端長人的防守加分），故 ρDef 的門檻只設在不低於 E2 基準（見第三節）。

### G3：G2 ＋ RAPM 目標對齊（唯一能向下修正的機制）

```
align(i) = delta * (r(i) - pred0(i))                     若 pooledPoss(i) >= 5000
         = 0                                              其餘
pred(i)  = pred0(i) + align(i) + gamma * max(0, centeredD(i)) * w(i)
```

- **固定先驗**：`δ ∈ {0.25, 0.4}`，`γ` 取 G2 選出的代表值，`w` 同 G2（`PR_lo/PR_hi = 90/96`，
  且 `PR` 一律用 `pred0` 算，不用對齊後的值，確保可重現且不循環依賴）。
- **意義**：等價於「對 `pooledPoss ≥ 5000` 的可靠樣本，把混合目標的 RAPM 權重從 α=0.5 再往上推
  δ 比例」，是一個雷同 F1 但作用在 `pred` 後處理、不重新擬合的版本。**不是自由回歸係數。**
- **預期副作用**：Mobley −0.61（δ=0.4）、Karlo −0.91、Stewart −0.74；側翼／後衛再加
  +1.2～+1.8（Jones、Caruso、Wagner）。**Embiid +0.43、Gordon +0.37 會被往上推**，與「前十長人少」
  的目標反向。Jamal Murray（RAPM 第 211、2K27 第 21）會被下壓約 −1.3，Jalen Duren、Paul Reed、
  Ryan Rollins 等 RAPM 差但卡片高的球員同樣下壓。
- **對 9 項門檻的侵蝕風險**：**Gobert（r−pred = +1.52）、Queta（+2.04）會進一步上升，門檻更安全；
  Karlo／Stewart 下壓，掉名門檻更安全；Collins（RAPM 第 240）、Garza（RAPM 第 174）預期也下壓，
  門檻更安全。Jalen Smith（r−pred = +1.04）會上升，δ=0.4 時約 +0.41，從第 152 往上移，門檻是
  `≤ 220`，方向安全。** 真正的風險集中在 **ρ(2K27)**：2K27 與 RAPM 在 Murray、Caruso、Thybulle、
  Duren 等人身上嚴重不一致，δ 越大越偏向 RAPM，ρ(2K27) 可能跌破地板（這也是 v56 的 F1-β1.0 失敗的
  同一個機制）。
- 這個方向之所以值得跑，是因為 1.3／1.6 證明：**不用它就無法把 Mobley 移出前十**，而「只加分不扣分」
  的 G1／G2 在前十長人問題上的上限就是回到 E2 的 5 人（含 Mobley）。

### G4：純對齊對照組（只有 G3 的 `align`，沒有任何防守加分）

```
pred(i) = pred0(i) + delta * (r(i) - pred0(i))           若 pooledPoss(i) >= 5000
```

- **固定先驗**：`δ = 0.4`（單一值，與 G3 的上界同值，便於歸因）。
- **目的**：純對照。1.6 顯示側翼被 `r` 大幅上拉、Mobley／Karlo 被下壓，**有可能光靠對齊就同時解決
  兩個問題**。若 G4 的表現不輸 G3，則應優先採用更簡單的機制（少一個 γ、少一個 taper）。
- **已知量測偏誤（必須在報告裡寫明，不能當成功績）**：`ρ(RAPM pooledNet)` 對 G3／G4 **會因為機制
  本身而機械性上升**（把預測值往 RAPM 拉近，相關係數自然變好），所以 **G3／G4 的主要判準是
  `ρ(2K27)`（完全外部、不在目標裡）與個別球員門檻，`ρ(RAPM)` 只當作不可退步的下限，不能當作優劣
  排序依據。** 選版規則第三節已據此設計。

## 四、選版規則（跑結果前鎖定）

1. **方向內選代表**：每個方向（G1、G2、G3）在自己的候選值裡，先取「通過硬門檻數最多」者；同分時
   取 **ρ(2K27) 較高**者；仍同分時取「前十長人數較少」者；再同分取 `γ`／`δ` 較小者（偏好較小的
   干預）。G4 只有單一候選值，自己就是代表。
2. **跨方向選最終建議**：在全部通過 19 項硬門檻的方向代表裡，取 **ρ(2K27) 最高**者。
   - ρ(2K27) 是唯一完全不在校準目標裡的外部信號；G3／G4 的 ρ(RAPM) 會機械性上升（見 G4 的說明），
     **一律不得用 ρ(RAPM) 的高低做跨方向排序**。
3. **若沒有任何方向代表全過 19 項**：
   - 取通過數最多者；同分時取 ρ(2K27) 較高者。
   - 若「側翼門檻（第 10～13 項）」與「前十長人門檻（第 15～17 項）」出現**無法同時滿足**的情況，
     **不自動升為正式卡片**，改為在報告裡並列兩個候選（側翼最佳 vs 前十最佳）＋各自的完整門檻表，
     交由使用者裁決。這是本輪就預先寫死的規則，避免下一輪私自放寬門檻。
4. **正式卡片的切換條件**：最終建議版本必須同時 (a) 全過 19 項硬門檻，且 (b) ρ(2K27) ≥ F2-γ0.5 的
   0.4878（不只是地板 0.4828）。否則只提出建議、不切換正式卡片，正式卡片維持 E2-λ0.4（並說明
   F2-γ0.5 是否仍是較佳選擇）。
5. **不做的事**：不放寬 E2 的吃餅折扣；不自由估計任何新係數（所有 γ／δ／PR 錨點都是本文件寫死的
   固定先驗）；不在看到結果後新增或修改門檻數字；不修改 `data/`、`scripts/build_season_league.js`、
   `runs/`、既有 `reports/` 下任何檔案。
